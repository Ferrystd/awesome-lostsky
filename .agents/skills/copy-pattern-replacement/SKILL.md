# 文案替换图案

目标是用最少上下文和最小 diff 完成一次可验证的精确替换。

## 必需输入

- 目标页面：当前打开页面、页面 URL 或应用路由三者之一；
- 目标文案（可逐字提供，或描述它在页面中的唯一可见位置）；
- 替换图案（逐字提供，或给出仓库内素材路径）；

源码文件路径是可选的加速信息，不要求用户提供。

图案是素材时，还必须给出替代文本或确认它纯装饰；不要自行生成、下载或挑选素材。

## 执行

1. 先读取仓库 `AGENTS.md` 和本任务直接相关的项目规则；这些规则仍然优先。
2. 优先从页面的可见文字与元素层级确认目标；用户已逐字提供文案时，不必打开页面。只在需要消除歧义时使用浏览器读取当前页面或给定 URL，不截图、不做视觉巡检。
3. 若给出文件路径，只检查该文件；否则用确认后的文案以 `rg -nF -- "<目标文案>" frontend` 定位源码。找不到或命中多处时，结合页面位置缩小到唯一位置；仍不唯一才提问，不猜测替换位置。
4. 只替换确认的一个渲染位置，保留周边结构、样式、事件、i18n key 和其他相同文案。图案应使用已有组件或原生标记，不新增抽象、依赖、路由或素材。
5. 仅在需要时补充无障碍语义：纯装饰使用 `aria-hidden="true"`；承载信息时使用用户提供的替代文本。
6. 用 `git diff --check` 和固定字符串搜索验证：旧文案不再出现在目标位置，新图案恰好出现在确认的位置。报告修改文件和实际检查结果。

## 成本边界

- 不启动子 agent，不进行设计探索、截图巡检或全仓扫描。
- 不要求用户寻找文件；页面、可见文案与图案足以开始。
- 不运行全量构建；仅在仓库强制规则、类型变更或用户明确要求时运行对应检查。
- 如果请求缺少目标文案、图案或唯一位置，只提一个最短的澄清问题后停止。
