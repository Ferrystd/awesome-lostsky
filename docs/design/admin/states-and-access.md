# 状态、权限与能力

## 不越权、不误报

已知缺少权限或能力时不得发起受保护请求。既有入口保持结构稳定并使用真实 disabled 语义、禁用原因和无障碍名称；页面加载时不得弹出权限错误，只有用户主动触发禁用入口时才显示一次短时说明。

权限与 Ability 是不同边界：权限决定主体能否执行操作，Ability 决定团队是否具备业务能力。两者都不得通过“先请求、收到 403 再隐藏”实现。4xx、权限和能力错误不自动重试；仅网络或 5xx 临时错误最多自动重试两次。

## 异步状态

- 首次加载使用与最终结构相近的骨架，不使用空白页面。
- 空状态说明当前为何为空及下一步；筛选无结果与尚无数据使用不同文案。
- 真实失败只在问题区域显示一次，不同时弹全局提示；顶栏、导航和未受影响内容继续渲染。
- 普通页面不提供手动刷新或重试按钮。数据在首次进入、窗口重新聚焦、网络恢复和操作后缓存失效时更新；窗口从后台重新成为可见页面时必须重新校验查询，即使旧数据仍在缓存中。4xx、已知权限和已知能力错误仍不得借此重复请求。
- 异步路由必须有错误边界；响应缺少可选集合时归一化为空数组，不得直接调用 `.find/.map/.filter` 导致整页崩溃。

## 上传与部分能力缺失

缺少上传 Ability 时 URL 输入可继续使用，文件选择稳定禁用并说明原因；不得显示易被理解为系统报错的常驻警告。部分下拉选项缺失时表单仍渲染，只禁用受影响字段并显示中性说明。

## 允许例外与检查

破坏性操作的二次确认、认证失败后的重新登录，以及用户明确提交失败后的再次提交不属于“手动刷新/重试”。检查网络日志：禁用入口请求数为 0；首次加载无权限 Toast 为 0；4xx 重试为 0；网络/5xx 总尝试不超过 3 次；任一 API 异常不导致壳层空白。
