# 状态、权限与能力

## 不越权、不误报

1. **范围**：所有后台工作台中可由访问快照提前确定的 Permission 与 Ability 限制，包含概览入口、导航、页面数据和业务命令；认证失败、身份恢复、外部 Entity 警告、字段校验和真实请求故障不属于本规则。
2. **入口**：应用入口、侧栏导航、概览卡片和页面路由始终开放，不因 Permission 或 Ability 隐藏、禁用、拦截导航或改跳错误页。列表或详情中的“新建、编辑、查看、审核、绑定、充值”等按钮只要作用是进入另一个任务页面，就属于入口，不得使用权限态；进入目标页面后才按数据形态降级，真正提交业务命令的按钮再校验 Permission 与 Ability。
3. **列表数据**：读取因 Permission 或 Ability 被拒绝时，把集合归一化为空数组并保留拒绝原因；受限空状态使用 `LsEmptyState` 显示“无法读取数据”和对应 Permission / Ability 的统一格式化原因，不得显示“暂无任务”等正常空文案。
4. **普通数据**：详情、表单、摘要和单值字段读取因 Permission 或 Ability 被拒绝时统一显示 `-`，不得显示权限警告、区域错误、页面文案、悬停 `title` 或常驻原因。路由壳层不得用统一状态页替换真实业务页；页面标题、说明、筛选器、字段标签、内容分区与操作区必须照常渲染，只在原数据位置降级。普通数据授权原因通过 `feedback.info()` 短时弹窗说明，列表由受限空状态说明。
5. **操作按钮**：命令统一使用 `LsButton` 或 `LsPagePrimaryAction` 的 `disabled + disabledReason`。按钮只以比正常状态更灰的既有权限态降权，不增加锁图标、警告色、禁用标签或原因文案；仍可聚焦、可点击并带 `aria-disabled="true"`，点击或键盘触发后才由 `feedback.info()` 显示一次 3–5 秒短时说明，请求数保持为零。Permission 必须先于 Ability 判断。
6. **请求与例外**：通用请求器必须识别服务端结构化的 Permission 与 Ability 拒绝。读取请求被拒绝后调用 `feedback.info()`，并向页面提供空集合降级结果；写请求被拒绝后调用 `feedback.info()` 并保留失败语义，但 `friendlyError()` 不得再次生成可见授权文案。已由访问快照确定的限制可在页面进入时直接调用 `feedback.info()`，不重复发送受保护请求；4xx 不自动重试。身份页与外部身份警告按各自安全流程展示。
7. **验收**：所有入口均可导航，特别是无 Permission、无 Ability 时仍可从列表点击进入全部新建、编辑、查看、审核、绑定和充值页面，真实页面结构始终存在；受限列表显示对应授权原因，不误报为正常空数据，普通数据仅在无法读取的关键值位置显示 `-`，不得把整个页面缩减为单个横杠；每次进入受限数据页只出现一条 `feedback.info()`，授权原因只在受限空状态中保留，不增加页面警告条；受限业务提交按钮的视觉透明度低于正常按钮，鼠标与键盘触发后各只出现一条格式化说明且不发请求。桌面、移动端、200% 文本和减少动态模式结果一致。

Permission 决定主体能否执行操作，Ability 决定团队是否具备业务能力。无论拒绝来自访问快照还是实际请求，列表授权原因由 `LsEmptyState` 呈现；普通数据和操作授权原因由 `feedback.info()` 呈现。

## 异步状态

每次访问因 Permission / Ability 降级为空列表或横杠的数据，都必须触发一次 `feedback.info()`，包括概览内的局部业务读取与表单内的局部候选读取。已知限制可跳过请求，但不能跳过提示；先等访问快照或能力信息确认，不能在加载中猜测权限缺失。空状态组件仅负责持久展示原因，不自行重复触发弹窗。

详情主查询通过 `useRouteAccess().read()` 识别请求器返回的拒绝结果，记录当前页面的受限原因并返回 `null`，不得把受限空数组交给详情渲染或表单回填。服务端拒绝优先于缓存的访问快照；成功读取或切换路由后清除旧拒绝原因。列表继续保留空集合及其拒绝元数据，局部候选受限不能关闭整页。

- 首次加载使用与最终结构相近的骨架，不使用空白页面。
- 空状态说明普通的空数据结果与下一步；筛选无结果与尚无数据使用不同文案；读取受限必须切换为对应 Permission 或 Ability 原因。
- 真实失败只在问题区域显示一次，不同时弹全局提示；顶栏、导航和未受影响内容继续渲染。
- 普通页面不提供手动刷新或重试按钮。数据在首次进入、窗口重新聚焦、网络恢复和操作后缓存失效时更新；窗口从后台重新成为可见页面时必须重新校验查询，即使旧数据仍在缓存中。4xx、已知权限和已知能力错误不得自动重试。
- 异步路由必须有错误边界；响应缺少可选集合时归一化为空数组，不得直接调用 `.find/.map/.filter` 导致整页崩溃。

## 上传与部分能力缺失

缺少上传 Ability 时 URL 输入可继续使用，文件选择保持原有权限态，触发后仅由 `feedback.info()` 说明原因；不得显示常驻授权文案。部分下拉选项因授权限制为空时表单仍渲染，关键值使用 `-`。

## 允许例外与检查

破坏性操作的二次确认、认证失败后的重新登录，以及用户明确提交失败后的再次提交不属于“手动刷新/重试”。检查网络日志：访问快照已知受限按钮请求数为 0；数据请求收到结构化授权拒绝后不重试；每次拒绝只有一条 `feedback.info()`；受限空状态包含对应授权原因且不显示正常空文案；网络/5xx 总尝试不超过 3 次；任一 API 异常不导致壳层空白。
