# Weibo 应用

Weibo 是团队上下文的微博账号、点单信息流、自动发帖与每日签到工作台，前端入口为 `{slug}.weibo.lostsky.work`，开发端口为 `5181`。使用方法见[微博工作台](https://doc.lostsky.work/app/weibo/)，接口契约见 [`weibo.openapi.json`](../openapi/weibo.openapi.json)。

## 鉴权边界

- 基础概览和访问快照不要求 Weibo Permission 或 Ability。
- 团队业务导航、数据读取与本地管理要求 `weibo.team.manage`；个人对应操作要求内部 Entity 与 `weibo.personal.use`。
- 团队范围接受本团队 Entity，或获得目标团队角色的外部有效 Entity；个人范围仍由服务端固定为当前团队内的 Entity。
- 手动发帖、点赞、评论，任务开启/恢复、Worker 实际执行及信息流完整读取要求 Weibo Ability。
- Permission 或 Ability 缺失不会在页面加载时主动报错，也不会显示常驻原因或悬停提示；受限入口和业务按钮仅做灰度降权，保持可聚焦、可点击，用户点击后才短时说明原因且不发受保护请求。
- 团队可管理既有个人任务，但团队创建接口只能创建 `owner_entity_id = NULL` 的团队任务。
- Worker 执行已经运行的任务不回查创建者当前 Permission，只按团队 Weibo Ability 与账号、任务状态执行。

## 点单信息流

个人工作台提供固定的“点单信息流”，面向寻找付费陪玩、代打、有偿服务点单及微博站内抽奖的帖子，排除服务广告、招聘、引流、故事分享和站外抽奖。首版使用平台统一关键词与判定规则，不提供团队自定义检索。信息流按微博发帖时间倒序显示纯文字、时间和作者，不展示图片；页面定期获取数据库中的最新结果，采集任务独立运行，不由每位用户访问触发远端搜索。

- 匿名搜索移植 `weibo-workflow-export` 的临时访客流程：取得访客 Cookie 后访问微博 Web 搜索接口。它只有分页参数，没有时间戳增量游标，也不保证结果按发布时间排序。每轮扫描有界页数，使用微博 ID 唯一去重；不能遇到旧帖就提前停止整轮检索。
- 仅新增或等待有限重试的帖子进入本地模型判定，已完成的正、负判定长期保留并参与去重，不随模型切换自动重判。搜索失败、模型超时和非法响应不能当作“无点单意图”。默认采集、展示最近 24 小时帖子；超过显示窗口的记录继续保存在数据库，采集器不做物理删除。
- 搜索文本优先读取接口携带的完整长文，其次读取纯文本与去标签后的正文。明确标记为长文但没有完整内容的记录跳过；转发只判定外层发帖人的文字，不拼接被转发原文。搜索结果并不构成全站覆盖承诺。
- 分类使用常驻本地 MacBERT 服务，批量提交原始正文。推理仅删除开头第一个完整超话标签，数据库原文保持完整。固定第三轮权重、分词器、最大长度 160 与阈值 `0.46`，PHP 校验服务身份、预处理指纹、逐条 ID 和概率范围；本地服务失败时保留 Failed 并有限重试，不回退远端分类。部署与资产核验见[信息流部署](../operations/deployment.md#weibo-feed-polling)。
- `GET /personal/feed` 是明确的受限预览例外：只向当前团队内部的 Team、成员或虚拟人员开放。缺少 `weibo.personal.use` 或 Weibo Ability 时，服务端仍返回列表，但正文仅保留首尾片段，短正文也不能完整返回；省略作者、远端微博标识和全部跳转地址。前端不得通过完整正文加遮罩实现降权。
- 完整阅读、打开原帖和信息流目标评论要求个人 Permission 与 Weibo Ability。跳转先尝试微博客户端，不能唤起时回退网页；受限按钮沿用灰态、可聚焦、点击后短时说明原因的行为。预览不改变既有账号、任务和日志的权限规则。
- 信息流已有缓存时，来源更新或后台查询失败仅在列表区域持续显示一条错误，保留已加载帖子，不重复弹全局提示；自动刷新恢复后移除错误。追加加载失败仍在列表尾部单独说明，并保留显式继续加载入口。
- 评论由用户选择当前身份已绑定的账号，确认文本后手动发送；服务端从本地帖子定位远端目标，校验当前身份及账号范围，再复用既有单次写入和操作日志。失败或结果未知均不得显示为成功，也不得自动重发。

## 互动与页面间导航

信息流的“评论”在当前帖子下方滑出两行紧凑编辑栏：上行横向滚动显示全部团队和个人预设气泡，长文案只在气泡内截断，点击后将完整内容填入下行输入框；下行输入框和发送按钮并列，用户仍可修改并手动提交。列表上方统一选择发表评论使用的当前身份已绑定微博账号。各帖子独立保留草稿，收起、刷新列表和切换微博账号不覆盖内容；离开、刷新和关闭使用共享未保存守卫。权限或身份撤回时关闭编辑区并阻止提交，身份切换清除旧草稿和账号。提交捕获帖子、账号、身份和文本快照，同一帖子处理中不重复发送；成功只确认已提交快照，较新草稿保留，失败保留内容，结果未知提示先核实且不自动重发。

账号字段由应用内 `WeiboAccountField` 统一负责；信息流使用专属 `WeiboFeedCommentComposer`，28px 常规字重的快捷预设 chip 与输入/发送组成低矮两行面板，独立互动保留 `WeiboCommentFields` 的完整表单。各组件负责可访问名称、加载、候选错误、权限显示和输入控件，参数仅表达业务数据、状态、语义 ID 与模型/发送事件；不再保留 `feedRail` 视觉开关。页面负责请求、权限、草稿和操作结果。独立互动页继续支持选择账号、点赞或评论。团队预设由互动页进入，侧栏保持“互动”选中；个人预设管理入口移至信息流标题栏，个人互动不重复提供。个人预设列表、新增和编辑页沿用现有 URL，侧栏选中“点单信息流”，列表固定返回信息流，不接受 query 改变返回目标。

信息流进入个人预设管理时，在现有会话导航模块按团队、身份和个人范围保留逐帖草稿及账号，不写入 URL 或本地存储。返回（含浏览器后退）仅恢复当前仍可读取的有效帖子；身份变化、权限撤回或离开该辅助流程时丢弃缓存。发送期间阻止进入管理并说明原因；只有成功保留草稿的辅助往返免除离开确认。入口在空、错误和受限状态仍可进入，本地维护预设不要求 Weibo Ability。

团队互动为 `/interactions`，个人为 `/personal/interactions`。query 契约如下；所有参数均为单值，重复值拒绝，未知参数不进入表单或提交：

| 参数 | 用途与边界 |
| --- | --- |
| `action` | `like` 或 `comment`，缺省为 `like`；信息流目标只支持 `comment` |
| `feed_post_id` | 个人信息流的正安全整数标识；通过 `GET /personal/feed/{id}` 获取当前仍有效且有权读取的帖子，提交仍使用原信息流评论端点 |
| `status_url` | 普通互动目标链接，按微博正文页协议、域名与路径校验；不能与 `feed_post_id` 同时提供 |
| `from` | `feed` 表示返回个人信息流；预设管理往返使用 `interaction`，不接受任意返回地址 |
| `draft` | 仅用于当前应用内存中的草稿令牌，不包含正文；失效或上下文不匹配时回到稳定父页面，不恢复其他任务 |

非法目标不会降级成其他对象，参数只预填，不自动请求写接口。目标失效或读取失败时保留表单结构并阻止发送；读取受限值按普通数据规则隐藏。个人信息流单条读取要求完整 Permission 与 Weibo Ability，拒绝时不返回完整正文或链接；列表受限预览契约保持独立。

进入预设管理后再返回，恢复评论内容、账号与操作选择；普通离开和同页切换目标先保护未保存修改，取消则保留地址和草稿。恢复范围限定当前应用会话、团队、身份、工作台及任务，刷新或关闭后不承诺恢复；query 和后台回包不能覆盖新草稿。信息流向下滚动时自动追加帖子，不提供页码分页，也不读取或生成 `page` query；API 内部继续按批次分页。往返互动时从当前团队、身份和权限范围的会话查询缓存恢复已加载批次及浏览位置，权限变化不得恢复旧完整正文；追加、去重、失败恢复与末尾状态遵循[信息流页面契约](../design/admin/applications.md#weibo-feed-page-contract)。

## 预设评论

团队管理维护团队公用预设，个人维护当前 Entity 的预设；个人互动页发表评论时合并展示两者并标明来源。团队预设只允许 `weibo.team.manage` 修改，个人预设只允许内部 Entity 持有 `weibo.personal.use` 时读取与修改，本地维护不要求 Weibo Ability。

每个范围最多 20 条，每条最多 500 字，以整组文本一次原子保存；个人请求携带 `expected_entity_id` 防止旧页面在切换身份后误写。预设只是可编辑的评论草稿，不会自动发送；后台刷新不能覆盖未保存草稿。

预设列表只展示和搜索内容，预设归入互动子页面 `/interactions/comment-presets`，新增与编辑分别进入其 `/new` 和 `/edit`，个人工作台使用 `/personal` 前缀。新增入口不受读取或写入权限限制；进入后无法读取的既有值显示为 `-`，可填写新增草稿，实际保存仍按 Permission 拦截并说明原因。新增会保留已读取的本范围内容，与追加内容一起原子保存；读取失败或被拒绝时不得提交空集合覆盖旧内容。

## 协议与运行边界

协议服务移植 Weico 6.4.7 的动态 `from`、本地 `s`、超话、图片上传、登录检查、写接口和 `/page/button` 超话签到。首版不提供从已有微博帖子读取或导入图片；普通点赞和评论请求接收微博正文页链接（信息流评论由服务端按本地帖子标识定位），由服务端在远端写入前解析目标 ID。账号凭据开发阶段在数据库明文保存，但模型序列化、响应和日志都排除凭据。真实写操作一次最多调用一个远端写接口且不自动重试。自动发帖和每日签到共用 `weibo-schedule` 队列、Ability/登录阻塞、dispatch 防重与结果日志；签到额外按服务端自然日防止重复尝试。

任务开启/恢复和下一周期安排在同一短事务内更新任务并插入业务数据库 `jobs`，入队失败整体回滚；微博队列固定使用 `database` 连接且其 `connection` 为 `null`，与业务 ORM 共享事务。Worker 在账号检查后、领取 `dispatching` 时及远端写请求前复核 Active、version 和 plannedAt；阻塞与下一周期更新也使用这三个条件，旧 Worker 不覆盖暂停、取消或恢复后的调度。网络请求始终在事务外；暂停无法撤回已发起请求，也不承诺消除最后复核到请求发起之间的瞬时竞态。

Worker 使用业务数据库 MySQL 会话级执行锁，按数据库与 task ID 互斥，覆盖账号检查、远端写入、结果回写与下一周期安排，跨版本和周期生效。获取锁后重新读取任务；队列重投遇到仍持锁的执行体只延迟 30 秒，不修改日志、推进周期或发送通知。连接必须为单主库、非持久 PDO 且禁用断线重连；原生 PDO 获取/释放锁，正常结束或异常退出时释放，进程死亡由数据库在会话关闭后释放。网络请求仍在事务外。

调度候选只包含任务范围内仍绑定的账号：个人任务限定 owner Entity，团队任务接受团队内任一绑定；同账号多绑定只检查一次。缺少 UID、from 或 gsid 的账号按无效登录态处理，不调用远端检查，继续尝试其他候选；所有候选均无效时阻塞。解绑使任务引用账号在其范围内不再有绑定时，立即将 Active 任务阻塞为 `account_unbound`，清空下次时间并增加版本；即使任务还有其他候选也执行这一即时阻断。团队账号仍有其他团队绑定时不受影响，暂停任务保留状态与版本。解绑、任务阻断与通知在同一短事务内完成，通知失败整体回滚；远端请求已发起后仍不能撤回。

意外执行异常保留原调度键并退避重试，间隔为 60、120、240、480 秒，随后最多 900 秒；指数在计算前截断，高 attempts 不发生数值溢出。同 task/version 的异常告警只发一次，通知自身异常也只释放一次 Job。锁建立或连接配置异常同样延迟 60 秒，不能绕过互斥执行。

`php think weibo:tasks-recover` 为 Active 但缺失对应 Job 的任务补投，包含历史入队缺口；保留原 task/version/plannedAt 和 dispatch key，已有待执行或已领取 Job 不重复投递。取得执行锁后发现已有 `dispatching` 才按失联恢复为 unknown，并推进下一周期，同一 dispatch key 不重复远端写入。Unknown 通知为“结果未确认”，只有明确 Failed 才通知“执行失败”。执行锁保证本地执行体不并发；原执行体死亡前远端已收到的请求仍可能在远端继续处理，不能保证跨周期内容绝不重复。部署后及定时恢复安排见[Weibo Worker](../operations/deployment.md#weibo-database-worker)。

已取消任务为终态，暂停不能使其重新恢复。团队管理员编辑个人任务时，账号及媒体仍按任务 owner 范围校验。复用已登录微博账号时短信使用独立内部 weibo_bind 用途，不要求该手机号注册平台用户；公开短信入口仅接受 register/login。旧缓存挑战在有效期内仍核验原 login 用途，新挑战不复用平台登录验证码。
