# Weibo 应用

Weibo 是团队上下文的微博账号、点单信息流、自动发帖与每日签到工作台，前端入口为 `{slug}.weibo.lostsky.work`，开发端口为 `5181`。使用方法见[微博工作台](https://doc.lostsky.work/app/weibo/)，接口契约见 [`weibo.openapi.json`](../openapi/weibo.openapi.json)。

## 鉴权边界

- 基础概览和访问快照不要求 Weibo Permission 或 Ability。
- 团队业务导航、数据读取与本地管理要求 `weibo.team.manage`；个人对应操作要求内部 Entity 与 `weibo.personal.use`。
- 团队范围接受本团队 Entity，或获得目标团队角色的外部有效 Entity；个人范围仍由服务端固定为当前团队内的 Entity。
- 手动发帖、点赞、评论，任务开启/恢复、Worker 实际执行及信息流完整读取要求 Weibo Ability。
- Permission 或 Ability 缺失不会在页面加载时主动报错，也不会显示常驻原因或悬停提示；受限入口和业务按钮仅做灰度降权，保持可聚焦、可点击，用户点击后才短时说明原因且不发受保护请求。
- 团队可管理既有个人任务，但团队创建接口只能创建 `owner_entity_id = NULL` 的团队任务。
- Worker 执行已经运行的任务不回查创建者当前 Permission，只按团队 Weibo Ability 与账号、任务状态执行。

## 点单信息流

个人工作台提供固定的“点单信息流”，面向寻找付费陪玩、正在点单的发帖人。首版使用平台统一关键词与判定规则，不提供团队自定义检索。信息流按微博发帖时间倒序显示纯文字、时间和作者，不展示图片；页面定期获取数据库中的最新结果，采集任务独立运行，不由每位用户访问触发远端搜索。

- 匿名搜索移植 `weibo-workflow-export` 的临时访客流程：取得访客 Cookie 后访问微博 Web 搜索接口。它只有分页参数，没有时间戳增量游标，也不保证结果按发布时间排序。每轮扫描有界页数，使用微博 ID 唯一去重；不能遇到旧帖就提前停止整轮检索。
- 仅新增或等待有限重试的帖子进入 Jev 判定，已完成的正、负判定在保留期内均参与去重。搜索失败、模型超时和非法响应不能当作“无点单意图”。默认保留最近 24 小时数据，过期记录清理后不再出现在信息流。
- 搜索文本优先读取接口携带的完整长文，其次读取纯文本与去标签后的正文。明确标记为长文但没有完整内容的记录跳过；转发只判定外层发帖人的文字，不拼接被转发原文。搜索结果并不构成全站覆盖承诺。
- Jev 使用 [TypeSafe 官方 HTTP 接口](https://docs.typesafe.ai/introduction/quickstart)，提交正文作为待分类数据，询问发帖人本人是否正在寻找付费陪玩；排除陪玩接单广告、招募和历史回顾。模型返回的概率必须通过范围校验，再按配置阈值决定是否入流。阈值筛选不等于人工确认，真实命中率需用业务样本评估。
- `GET /personal/feed` 是明确的受限预览例外：只向当前团队内部的 Team、成员或虚拟人员开放。缺少 `weibo.personal.use` 或 Weibo Ability 时，服务端仍返回列表，但正文仅保留首尾片段，短正文也不能完整返回；省略作者、远端微博标识和全部跳转地址。前端不得通过完整正文加遮罩实现降权。
- 完整阅读、打开原帖和信息流目标评论要求个人 Permission 与 Weibo Ability。跳转先尝试微博客户端，不能唤起时回退网页；受限按钮沿用灰态、可聚焦、点击后短时说明原因的行为。预览不改变既有账号、任务和日志的权限规则。
- 评论由用户选择当前身份已绑定的账号，确认文本后手动发送；服务端从本地帖子定位远端目标，校验当前身份及账号范围，再复用既有单次写入和操作日志。失败或结果未知均不得显示为成功，也不得自动重发。

## 互动与页面间导航

信息流只负责发现点单及打开原帖，“去评论”进入独立互动页，不在列表挂载评论表单或加载账号、预设。受限列表仍保留首尾片段，允许进入互动页，但不携带帖子标识或原帖链接。互动页统一选择账号、点赞或评论；团队和个人预设作为其子页面，侧栏只保留“互动”，子页面保持该入口选中。

团队互动为 `/interactions`，个人为 `/personal/interactions`。query 契约如下；所有参数均为单值，重复值拒绝，未知参数不进入表单或提交：

| 参数 | 用途与边界 |
| --- | --- |
| `action` | `like` 或 `comment`，缺省为 `like`；信息流目标只支持 `comment` |
| `feed_post_id` | 个人信息流的正安全整数标识；通过 `GET /personal/feed/{id}` 获取当前仍有效且有权读取的帖子，提交仍使用原信息流评论端点 |
| `status_url` | 普通互动目标链接，按微博正文页协议、域名与路径校验；不能与 `feed_post_id` 同时提供 |
| `from` | `feed` 表示返回个人信息流；预设管理往返使用 `interaction`，不接受任意返回地址 |
| `draft` | 仅用于当前应用内存中的草稿令牌，不包含正文；失效或上下文不匹配时回到稳定父页面，不恢复其他任务 |

非法目标不会降级成其他对象，参数只预填，不自动请求写接口。目标失效或读取失败时保留表单结构并阻止发送；读取受限值按普通数据规则隐藏。个人信息流单条读取要求完整 Permission 与 Weibo Ability，拒绝时不返回完整正文或链接；列表受限预览契约保持独立。

进入预设管理后再返回，恢复评论内容、账号与操作选择；普通离开和同页切换目标先保护未保存修改，取消则保留地址和草稿。恢复范围限定当前应用会话、团队、身份、工作台及任务，刷新或关闭后不承诺恢复；query 和后台回包不能覆盖新草稿。信息流分页使用正整数 `page`（非法值回退第 1 页），往返互动时恢复当前会话内的分页和浏览位置。

## 预设评论

团队管理维护团队公用预设，个人维护当前 Entity 的预设；个人互动页发表评论时合并展示两者并标明来源。团队预设只允许 `weibo.team.manage` 修改，个人预设只允许内部 Entity 持有 `weibo.personal.use` 时读取与修改，本地维护不要求 Weibo Ability。

每个范围最多 20 条，每条最多 500 字，以整组文本一次原子保存；个人请求携带 `expected_entity_id` 防止旧页面在切换身份后误写。预设只是可编辑的评论草稿，不会自动发送；后台刷新不能覆盖未保存草稿。

预设列表只展示和搜索内容，预设归入互动子页面 `/interactions/comment-presets`，新增与编辑分别进入其 `/new` 和 `/edit`，个人工作台使用 `/personal` 前缀。新增入口不受读取或写入权限限制；进入后无法读取的既有值显示为 `-`，可填写新增草稿，实际保存仍按 Permission 拦截并说明原因。新增会保留已读取的本范围内容，与追加内容一起原子保存；读取失败或被拒绝时不得提交空集合覆盖旧内容。

## 协议与运行边界

协议服务移植 Weico 6.4.7 的动态 `from`、本地 `s`、超话、图片上传、登录检查、写接口和 `/page/button` 超话签到。首版不提供从已有微博帖子读取或导入图片；普通点赞和评论请求接收微博正文页链接（信息流评论由服务端按本地帖子标识定位），由服务端在远端写入前解析目标 ID。账号凭据开发阶段在数据库明文保存，但模型序列化、响应和日志都排除凭据。真实写操作一次最多调用一个远端写接口且不自动重试。自动发帖和每日签到共用 `weibo-schedule` 队列、Ability/登录阻塞、dispatch 防重与结果日志；签到额外按服务端自然日防止重复尝试。
