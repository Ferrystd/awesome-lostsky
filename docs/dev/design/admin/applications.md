# 后台应用与页面规则

本页登记应用专属边界和页面例外；未登记的行为必须服从公共规范。

## Team、Shop 与 Transaction 工作台概览

1. **范围**：Team、Shop 与 Transaction 的团队工作台和个人工作台侧栏、移动端主导航及对应概览路由；Chat、商城顾客中心和公开页面不适用。
2. **行为**：六个工作台都必须把“概览”固定为首个导航入口，并绑定本工作台的概览路由；禁止隐藏、改名、改绑到具体业务列表或按 Permission 移除。团队模式与个人模式各自保留独立概览，跨应用进入个人模式时落到目标应用个人概览。
3. **实现**：沿用 `TeamShell`、`ShopManageShell` 与 `TransactionShell` 的现有导航数据和 `House` 图标；团队概览分别使用 `/`、`/manage`、`/overview`，个人概览分别使用 `/personal`、`/manage/personal`、`/personal`。六个概览统一使用 `LsWorkspaceOverview` 的身份锚点与业务插槽，各应用保持下文规定的独立业务构图，在主视觉中提供对向工作台入口，不新增应用下拉或分段式切换控件。
4. **适配**：桌面侧栏与移动端导航共享同一数据源；“概览”保持至少 44px 触控高度、可见键盘焦点、可读链接名称和当前路由状态。文本放大时允许标签自然占用既有导航空间；概览切换不增加动效，减少动态无额外例外。
5. **状态**：概览不要求具体业务 Permission；加载或摘要错误只影响身份、团队等摘要文字，不移除工作台操作或业务入口位置。全部业务入口使用真实链接并始终进入目标路由；缺少列表读取条件时目标页渲染普通空列表，普通数据的关键值只显示 `-`，列表授权原因显示在受限空状态中，普通数据原因通过 `feedback.info()` 短时弹窗说明。Shop 与 Transaction 团队概览只读取既有访问快照；Team 使用已有资源/身份摘要，Transaction 个人概览复用本人 `/personal/stats`，不请求团队全量业务数据。Transaction Ability 缺失时记账应用和读取入口仍保持可用，仅指定提交动作在点击后提示。
6. **路由**：Transaction 团队概览保留 `/overview`，应用根路径 `/` 重定向到概览，团队流水位于 `/transactions`。
7. **验收**：Vitest 静态契约断言三个壳层的团队与个人导航首项均为“概览”且无 Permission；Playwright 分别验证团队/个人概览可达、无权限时不发受保护业务请求，并在桌面与移动端确认导航可见；发布前运行类型检查、相关 E2E、文档构建和完整静态构建。

三个业务工作台的侧栏底部都只保留“切换身份”这一全局会话操作。入口必须保持至少 44px 触控高度，并与同栏导航图标、文字左对齐；桌面固定侧栏与移动抽屉沿用同一结构和 `NButton` 键盘行为，不得因组件库默认居中样式改变位置。加载、空、错误、Permission 和 Ability 状态均不隐藏该入口。验收以源码契约和三个已登记壳层的真实组件预览确认，并在 Shop、Transaction 的工作台 E2E 中读取实际 `justify-content`。

## Team

团队与个人概览均在摘要区提供 `TeamShareLinks`，复用访问快照中的当前团队 slug，展示商城首页、展示首页和 `/join` 入职表单的 HTTPS 正式链接。每项支持打开与一键复制，复制结果使用全局短时反馈；无法复制时可通过链接菜单复制地址。组件以公共 `LsPanel` 承载一个连续分享区，标题下为三个等分入口，使用细分隔线而非独立卡片或提示框；每项左侧为带外链箭头、用途说明的真实链接，右侧为公共 `LsButton` 复制命令，不显示冗长 URL。`TeamShareLinks` 是内部排版的唯一视觉所有者，无视觉参数；800px 以下切为纵向列表，链接和复制操作均至少 44px，键盘焦点可见，200% 文本放大无横向溢出，减少动态时取消颜色过渡。页面不穿透其样式，不新增业务权限或接口；快照加载或尚未提供团队 slug 时不生成链接，复制失败仍保留链接菜单恢复路径，无禁用态与额外例外。通过 `tests/team-share-links.spec.ts` 验证链接真值、复制成功/失败、两处概览、响应式几何和缺少 slug 的边界，并生成真实组件预览。

### 团队工作台导航

团队侧栏与概览共用 `workspaceNavigation.ts`，按“团队管理 / 人事管理”分组，概览固定首项。“人员管理”“顾客管理”“文档管理”使用完整任务名称，角色权限归入人事管理；成员管理保留独立生命周期任务，对象字段和虚拟实体从人员管理进入，团队能力从团队设置进入，子页面提供返回入口。移动底栏为概览、人员、顾客、更多；个人工作台保持独立。

审核列表组成“人事审核”，加入与复职、离队通过 `TeamSectionNav` 切换；申请表配置从加入页进入。当前人员收件箱及详情位于个人工作台 `/personal/notices`。团队“通知中心”默认打开 `/notices/sent`，查看本团队已发送通知、收件人员及已读状态，平台通知为另一页签，发送通知为页内入口。已发送列表与详情复用通知页面，要求 `team.notice.send`，后端按 `sender_team_id` 限定当前团队；查询不更新已读状态，写操作不接受 `sent` 范围。列表支持分页，团队概览通知计数为已发送总数。页签继续使用现有独立路由，支持刷新与详情返回，各自沿用原读取权限、查询及已读范围，入口不受业务权限隐藏或禁用。详情和提交页面保留独立任务，禁止合并数据范围。

概览的团队管理与人事管理上下排列，组内使用 Naive UI `NGrid` 与 `NThing` 展示可换行入口；按容器宽度由一列变为两列、三列，不拉伸两个不同数量的分组为等高双栏。页面只持有分组间距与链接交互表面，标题、描述和图标排列由 `NThing` 持有；入口始终可访问，摘要加载和错误不影响导航。通过桌面、移动端 DOM 几何断言检查分组顺序与入口不重叠，无例外。

`TeamSectionNav` 仅接收入口和无障碍名称，内部使用 Naive UI Tabs，移除默认页签垂直内边距，由路由链接统一持有 44px 触控高度及水平内边距，页面不得穿透样式；桌面与移动支持键盘、焦点和窄屏滚动，加载、空与错误由原列表处理，无额外动效或例外。通过 Team 导航 E2E 验证页签切换、受限数据、返回和横向溢出，公共源码守卫、类型检查及完整静态构建共同验收。

- Team 团队工作台保留既有顶栏与侧栏，概览正文遵循[差异化应用概览](#application-dashboards)。概览深色主视觉提供“进入个人工作台”；顶栏右侧直显团队、商品、记账、聊天和微博五入口。Team、Shop、Transaction 与 Weibo 均禁止使用应用下拉或分段式工作台切换控件。
- Team 个人工作台侧栏底部保留“切换身份”入口；概览主视觉另以新标签页打开用户指南的“使用文档”。身份领取与切换仍由 Account 身份页处理。
- 实体、成员、顾客及所有候选项统一使用 `LsEntityIdentity`；媒体为圆角方形，真实头像优先。此前实体与成员分别使用圆形和方形不是巧思，而是没有语义依据、会破坏主体识别的一致性问题，不得恢复。
- 实体、成员、顾客、文件、文档、角色、虚拟实体、申请字段、通知、加入审核是集合页，必须有 `LsListToolbar`。
- Team 文件列表在格式与大小旁显示首次上传类别（未知值统一显示“未知来源”），在文件名、格式和大小下显示来源人员与上传时间；来源复用紧凑只读 `LsEntityTag`，与上传时间以行内标签和值并排展示，禁止嵌入多行头像身份卡撑高文件行；仅消费文件记录的 `subject`，不推断业务页面或实际操作账号。无关联人员显示“未记录”，关联资料不可用时保留人员编号；无有效时间显示“未记录”。同内容去重沿用原记录来源与时间。元信息由 FilesView 持有，移动端元信息自然换行且操作移至下一行，不穿透公共组件。加载、空、错误和权限沿用现有列表状态，无新增例外；以文件列表 E2E 验证来源、缺失数据及桌面和移动端溢出。
- 成员移动端以“管理/查看”为主操作，对话、预览、封禁、离职进入更多；危险操作不得成为主操作。
- 顾客列表不得再嵌套第二个 `LsPage`；通知和审核使用连续列表。
- 顾客详情在同一资料表单中使用 `LsEntitySelect multiple` 维护协作发单人，与其他顾客字段一次保存；不新增独立绑定页、二次确认或页面私有选择控件。只读状态仍显示现有协作 Entity。
- 实体、成员、顾客、文件、文档、角色、虚拟实体、对象字段、申请字段、通知、加入审核、资源页和团队设置的页面级无数据统一使用 `LsEmptyState`；创建入口仍位于页面标题，不进入空状态组件。
- 上传缺少 Ability 时只禁用文件选择，不显示常驻错误。加入申请的动态文件字段统一使用 `LsUploadField`，其余动态字段使用对应 Naive UI 控件；缺失必填项时阻止提交并在字段区域说明，不得让协议字段回退到页面级原生控件。
- 加入申请页仅在链接包含有效邀请参数时，以非输入控件只读确认当前邀请人，不允许申请人改写链接带入的来源；没有邀请参数时不得渲染邀请人区域，页面结构与引入该功能前保持一致。成员详情将加入时间与邀请人放在独立的成员信息区，邀请人必须按全局 Entity 展示并明确标注其他团队来源。
- Team 成员、个人资料与实体详情复用 `EntityProfileFields`；其中单文件资料上传统一交给 `LsMediaUploadField`。`EntityProfileFields.uploadFile` 回调接收可选来源参数 `attachment/markdown`，Markdown 图片固定传 `markdown`，其他媒体字段沿用默认 `attachment`；来源不改变上传权限和状态。Team、成员与虚拟实体本人编辑位于 Team 个人工作台，并复用公共字段与权限卡片。Team Entity 的字段和业务内容按类型与参与关系受限；身份领取留在 Account，顾客资料留在商城顾客中心。文档、文件和资源目录的行内动作统一使用 `LsResponsiveActions`；文件与文档分页统一使用 `NPagination`。
- 文档编辑页的 `LsMarkdownEditor` 是第三方编辑器实现级例外：保留其原有的模式切换、候选项与工具栏视觉结构，不将 `NRadioGroup`、`NButton` 或 `NInput` 的通用皮肤套入编辑器内部。页面其余字段仍使用标准 Naive UI；验收时确认编辑器模式、源码与对象候选项和统一化前版本一致。
- 文档创建/编辑页的文档标签与实体资料管理页的公开文档分组统一使用 `LsFormList`。两处都允许添加、删除、拖拽及按钮排序，并按顺序提交；标签错误必须就近阻止保存。公开文档分组只出现在 Team、Member 和 Virtual 实体，Customer 不显示；缺少 `team.entity.profile.manage` 时展示只读内容并禁用列表变更，不发写请求。
- 团队设置各应用分组的保存动作统一使用 `SettingsSaveButton`：桌面端固定为紧凑的 `9rem` 等宽按钮，小于 640px 时铺满标题动作区。宽度由该 Team 业务组件内部持有，不得由设置页面穿透、传参或复制 CSS；其他 `LsButton` 与 `LsSectionHeader` 动作不继承此等宽规则。

### Team 资料表单尺寸

1. **范围**：Team 实体资料页、顾客详情页及其使用的 `EntityProfileFields`、`LsMediaUploadField`；列表、设置页和商城顾客中心不适用。
2. **行为**：实体资料表单中的命令必须紧凑且由所属语义组件统一管理：上传命令在各媒体字段中等宽，添加和保存不得被页面拉长；不同任务不为视觉齐边强制等宽。顾客详情与实体详情的摘要、资料面板和字段使用同一个 `form` 页面宽度，禁止用更宽面板包住窄表单形成无用途留白。
3. **实现**：`LsUploadField` 在自身语义内固定紧凑上传命令，`LsFormList` 与 `LsFormActions` 的添加/保存命令按文案自适应并保持最小触控宽度；不同任务不共享全局等宽令牌。实体资料页与顾客详情页只组合这些语义组件，不得穿透内部节点或传递视觉参数。两页均使用 `form` 容器，表单字段继续使用 `LsField` 与 Naive UI 控件。
4. **适配**：小于 640px 时上述按钮改为容器满宽，资料字段保持单列，320px、200% 文本缩放及长 URL 不得产生横向滚动；键盘、读屏和焦点顺序不因宽度调整而改变，减少动态不适用。
5. **状态**：默认、禁用、上传中、保存中及权限只读状态保留相同宽度；读取错误和加载骨架仍占用当前页面容器，不切换为宽容器；空状态不适用于详情资料表单。
6. **例外**：顶栏对话入口不属于表单命令组，保持内容自适应宽度；资料页设置动作必须进入 `LsFormActions`，无页面级尺寸例外。
7. **验收**：组件测试锁定上传局部固定宽度、添加/保存内容自适应和移动满宽契约，源码守卫禁止页面穿透 `.ls-*`、直接 `NSwitch` 与开关轨道文字。Playwright 检查命令触控尺寸、不过长和移动满宽；源码契约锁定实体与顾客详情使用 `form` 宽度。实体详情把团队内可见与公开主页展示合并在唯一“可见性设置”面板，只保留一次原子“保存可见性”，并覆盖脏草稿、刷新保护和只读同构状态。`LsSwitch`、`LsSwitchField`、`LsMediaUploadField` 与 `EntityProfileFields` 真实组件预览覆盖相关状态，发布前运行前端测试、类型检查、文档构建及完整静态构建。

### Team 高级范围权限

1. **范围**：仅适用于 Team 角色详情的团队 Permission 配置和成员角色摘要；平台 Admin RBAC、成员直授及其他应用不适用。
2. **行为**：普通权限区将身份领取与指定实体 assume Permission 合并为默认折叠的“实体委托”，把虚拟实体维护放入“实体管理”，把仅限聊天的虚拟实体代操作放入“聊天”；“高级范围权限”按相同业务分组展示父键。每项显示父键、当前覆盖数量和可展开叶子清单；选择父键或通配符会清理草稿中被覆盖的子键，取消后不恢复已清理项。本次新增父键保存前必须确认范围。
3. **实现**：目录以服务端 `groups` 和 `advanced_items` 为事实源，前端不得手输或推测未知键；加载只呈现服务端原始集合，点击保存时才按分段前缀与 `*` 规则提交最小 `permission_keys` 集合。服务端保存不同合法键时不做覆盖归并。成员页只分配角色，摘要逐条显示存储记录，并把实体委托父键留在平级“实体委托”组内同时标记“高级范围”。
4. **适配**：沿用后台单列、连续分隔列表与 Naive UI 控件，交互目标至少 44px；320px 下键、文案和数量可换行且不得横向溢出。折叠、搜索、复选框、叶子详情和确认弹层均可键盘操作、具有可读名称与可见焦点；不新增装饰动效。
5. **状态**：目录加载、保存错误和只读状态沿用角色详情现有反馈；空高级目录显示明确空结果，搜索无结果不影响已选草稿。被更宽父键覆盖的叶子与较窄父级显示覆盖来源并禁用；保存中锁定重复提交，取消确认返回原草稿。
6. **例外**：精确实体委托目标仍默认添加叶子权限，仅把其合法父键加入高级目录；`chat.virtual.<slug>.act` 直接列在“聊天”组，不进入实体委托目标编辑器。查看摘要不归并跨角色重复、父子或通配符与指定 slug 记录。拥有 `team.role.write` 者可配置当前团队完整目录，不要求自身拥有目标业务 Permission。
7. **验收**：Vitest 覆盖精确、父级、通配、兄弟匹配和父子去重；Playwright 覆盖选择 `team.ability`、二次确认、角色分配后入口可用，以及桌面、320px 与键盘操作；后端锁定目录生成、团队边界和即时生效。发布前运行后端权限测试、OpenAPI 路由测试、类型检查、完整 E2E、文档构建和静态构建。

### Team 成员离职

成员自助入口位于个人工作台资料页，无需成员管理权限；成员详情页的本人入口复用 `MemberSelfDeparture`。入口只渲染 `LsButton`，放入个人资料页与本人详情页 `AdminPageHeader` 的 actions 插槽，位于页面顶部右侧。移除底部卡片、独立标题和常驻说明，说明仅在 Naive UI 确认弹窗中展示。待审时按钮改为“取消离职申请”；读取失败时原位提供重试，失败原因使用全局反馈。不新增视觉参数或私有 CSS。组件负责申请读取、失败重试、提交确认、待审取消与自动批准后的身份页跳转，页面只决定位置与本人范围。加载或读取失败期间不允许提交；自动批准后不刷新已失效会话的数据，直接跳转到身份选择页，不显示离职结果，也不携带返回原团队的地址。服务端继续校验正常成员本人的直接登录会话、团队离队设置及 owner 限制。

### Shop 服务计量规则

5. **状态**：新建服务读取团队默认步长，编辑服务显示已保存步长；空值、零值、负值、超过四位小数或格式无效时禁止保存并由服务端返回可恢复的 422。权益继续使用领取时冻结的单位与步长，不被后续服务编辑追改。

7. **验收**：后端测试覆盖四种代表步长、无效步长和非步长倍数；前端源码契约禁止服务表单、Team 设置、类型与响应消费重新出现独立精度字段，并运行类型检查、服务核销回归、文档构建和完整静态构建。

### Shop 服务默认金额分配

以下服务、普通商品和权益包金额交互均受 [Shop 本人调价边界](../../apps/shop.md) 约束：个人缺少 `shop.product.self.reprice` 时，三项人员分成控件保持原位并只读，编辑时修改售价或成本不自动重算人员分成，新建商品/服务仍展示团队默认分成。权益包中本人服务只锁分成，公用服务同时锁价格与成本；复制新权益包按服务当前默认值建立受限基线。表单沿用 `LsField`、`NInputNumber`、已有单列布局与保存动作；无新增视觉参数、父级穿透或例外。桌面、移动端、键盘和加载状态均以同一规则呈现，服务端拒绝返回统一权限原因；通过个人调价 PHP 回归、Shop 表单 Playwright、类型检查和完整静态构建验收。

4. **适配**：桌面与移动端保持“价值 → 成本 → 接单 → 发单 → 客服 → 团队”的单列顺序；只读团队分配保留可见标签、数值和禁用语义，键盘跳过该控件，320px 与 200% 文本放大不得横向溢出。无额外动效。
5. **状态**：团队默认比例未返回前使用配置默认值；编辑页首次水合保留已保存的人员分配，只有用户随后修改价值或成本才按当前比例重算。空值、非有限值、成本高于价值或人员分配超过可分配金额时禁止保存；查询、权限和保存错误沿用现有页面状态。

### Account 登录页原生按钮例外

1. **范围**：仅适用于 `account/login` 的登录方式分段按钮和密码可见性按钮；注册、团队、身份及其他 Account 页面不适用。

5. **状态**：分段按钮只包含已选与未选状态，密码按钮只包含显示与隐藏状态；加载、错误、过期登录及禁用状态继续由原表单和提交按钮处理，不涉及权限、Ability、空数据或额外恢复流程。

7. **验收**：`npm test` 的源码契约锁定仅这三个原生按钮；`tests/frontend.spec.ts` 在桌面和移动项目中断言两个 tab 数量为二且纵坐标一致，并继续检查两种登录表单均可操作；发布前运行 `npm run typecheck`、对应 E2E 与 `npm run build`。

### 点单信息流与预设评论的页面契约

1. **范围与分组**：`/personal/feed` 的“发现最新点单”包含数量、更新时间和连续文字帖子；选择帖子后进入互动页“回复当前帖子”，账号、预设与正文共同服务于一次评论。团队及个人预设页的“维护常用回复”包含全部预设和一次原子保存，不为每条内容建立独立面板或保存动作。
2. **页面与操作**：信息流、互动及预设页面沿用 `App.vue` 中唯一的 `LsPage`，路由分别声明信息流与预设列表 `pageWidth="content"`、互动、预设新增和编辑页 `pageWidth="form"`，禁止页面再次嵌套同类容器。页内使用 `LsPageHeader`，标题说明只解释用户任务，不常驻显示轮询秒数等实现细节。信息流有内容时用 `NFlex` 将结果数量与更新时间合并为无边框的紧凑信息行，数量使用 `role="status"`，时间使用 `time` 并在 `datetime` 与 `title` 保留完整日期；连续帖子由 `NList bordered size="small"` 与 `NListItem` 统一边界和分隔，禁止用空搜索工具栏占位。信息流不显示页码或分页控件，接近底部时自动追加下一批，并按帖子 ID 去重；每条正文优先、完整展示服务端已提供的文本，不增加省略或行数裁切；时间与可用作者置于正文下方；打开原帖使用带图标和文字的 `LsButton variant="ghost"`，“评论”使用 `LsButton variant="ghost"` 在帖子下方展开评论区，设置 `aria-expanded/aria-controls`；列表上方通过 `WeiboAccountField` 选择本页评论账号，帖子编辑区由专属 `WeiboFeedCommentComposer` 拥有紧凑预设轨道和输入发送区；独立互动页使用 `WeiboCommentFields` 保留独立表单形态、`LsField` 标签和 `LsFormActions`；预设重复字段增删与排序由 `LsFormList` 负责，禁止页面重建行操作皮肤。
3. **状态**：首次加载与主查询真实失败使用 `LsAsyncState`。访问快照失败时同样显示明确错误状态并暂停信息流读取，不能误报无帖子或恢复旧完整正文。成功返回但来源未配置且没有帖子时，以 `LsEmptyState` 说明来源尚未就绪及联系管理员的下一步；来源正常但无帖子时显示正常空态；来源更新失败且没有帖子时显示 `LsAsyncState` 错误，不误报正常空数据。已有帖子遇到更新失败时保留内容，通过 `feedback.error()` 短时弹窗提示一次；状态未变化的定时刷新不重复弹出。追加加载由页尾 `NSpin` 与 `role="status"` 文本说明，失败由页尾 `LsInlineError` 和 `LsButton`“继续加载”提供显式恢复；错误后观察器和普通后台刷新不得反复自动重试失败批次，成功刷新确认已无后续批次时清除追加错误并显示“已看完当前点单”。末页使用同一紧凑状态，不渲染空白列表或空状态大面板。无内容时不得挂载空列表边线或单独“共 0 条”占位；不得直接展示采集器 `last_error` 等内部诊断。账号、预设等局部查询错误使用 `LsInlineError`，不能让局部失败替换互动表单。预设评论按集合处理：正常空集合使用 `LsEmptyState` 并保留标题区添加入口，读取受限使用同一组件显示统一拒绝原因，禁止用 `-` 代替列表；服务端拒绝元数据必须保留并优先于访问快照，列表标题的添加入口始终可进入 `/interactions/comment-presets/new`（个人范围带 `/personal` 前缀），不得因权限、读取失败或空数据禁用；列表有内容时提供编辑入口进入 `/interactions/comment-presets/edit`。列表不承载输入或保存。新增页读取现有范围集合后追加空项，编辑页维护完整集合，均由同一独立表单实现原子保存；不可读取既有数据时用 `-` 表示，新增页仍允许输入本地草稿，保存点击解释原因且不发送请求，不能把受限空结果作为可覆盖的集合。已有条目的增删排序仍由 `LsFormList` 持有；草稿超过 20 条时局部说明数量上限并禁止保存，删除多余项后可继续保存，服务端约束不变。
4. **适配与边界**：信息流在 768px 及以上把正文与动作排为左右两列，窄屏将动作置于正文和时间下方；DOM 顺序固定为正文、时间与作者、动作，长正文自然换行，短帖子不得设置固定高度或额外底部留白。页面只负责该业务结构的网格与间距，不穿透 Naive UI 或 LostSky 控件内部。`useInfiniteQuery` 缓存已加载批次；`IntersectionObserver` 距底部 240px 触发追加，短屏内容不足时继续填充；追加与每 30 秒的可见页顺序刷新共用查询并互斥，不覆盖正在获取的批次。以原始批次进度与总数判定末页，遇到空批次立即停止，不能用去重后的显示数量决定是否继续。页面隐藏时停止发起追加和轮询；权限模式变化以及离开期间权限改变后的重新挂载，均在真实模式确定后只按当前身份 scope 的 exact query key 清除非当前模式缓存并重置浏览位置，混合响应中的受限标记优先，禁止显示旧完整正文。离开再返回时从当前团队与身份的查询缓存恢复已加载列表和滚动位置，不因 mount 立即刷新；页面不再消费或生成 `page` query。行操作、字段和提交按钮遵循公共组件的键盘、触控与禁用解释契约。覆盖 320、375、768、1024、1440px 与 200% 文本，不允许横向溢出。加载、查询刷新与发送期间保留草稿；未保存离开保护沿用共享守卫；权限不足仍遵循上面的安全片段例外。
5. **具名例外**：信息流服务端当前没有全文搜索或筛选契约，因此不挂载 `LsListToolbar`，数量与更新时间并入列表上方信息行；不添加会误导用户的仅当前页搜索。该例外只适用于点单信息流；服务端提供搜索后应重新评估。页尾“继续加载”仅恢复失败的追加请求，是无通用刷新按钮规则的具名例外；初次读取和后台更新失败仍沿用现有自动恢复，不新增刷新或重试入口。列表内评论是连续处理点单的具名编辑例外：展开区为两行紧凑编辑栏；上行由 `NScrollbar` 横向滚动展示全部团队和个人预设气泡，预设为 `NTag checkable round` 的专属快捷 chip，原生 medium 高度 28px、常规 400 字重、8px 项间距，不套用普通命令按钮的尺寸、粗体或内边距；此 28px 触控例外仅限连续工作中的快捷预设，普通按钮仍遵循 44px。chip 设置可聚焦按钮语义、Enter/Space 单次选入、2px 焦点轮廓及轨道内4px留白，checked 与正文同步；可见内容只显示评论开头约 5 个汉字（标签文字上限 5em），不显示来源或勾选图标；完整可访问名称与标题保留团队/个人及全文，当前正文与预设相同时设置 `aria-pressed`，不另造按钮皮肤。长文案只在气泡内单行截断，按钮的可访问名称和悬停标题仍保留完整内容，点击后向下行输入框填入完整预设并允许继续修改，不自动发送。下行用 `NInput` 的 suffix 插槽承载圆形向上箭头发送按钮，输入 1 行起步、最多自动增高至 3 行；输入与按钮横向分配空间，不可遮挡正文。`WeiboFeedCommentComposer` 内的唯一 `NButton circle` 是 44×44px 纯图标微操作具名例外，保留“发表评论”的可访问名称，业务参数 `sending/submitReason` 和 `submit` 事件对接原有提交；禁用仍可聚焦并由 `feedback.info` 解释，发送中不重复提交。此例外仅用于该信息流专属组件，默认独立互动表单不使用；未来公共发送原语具备相同语义时迁移，并以精确源码守卫和点击、键盘、禁用/加载 E2E 验收。桌面和窄屏均保持两者并列；正常面板不重复增加顶部分隔线，预设轨道与输入间距4px，48px起步输入与28px预设形成明确比例；空白正文的正常展开区不超过96px，不产生页面横向溢出。无预设时省略上行；加载与局部错误保持简短提示，错误时仍可手填。未选账号由页面上方字段及发送按钮的禁用原因说明，编辑栏不额外增加第三行；发送失败在编辑栏下方显示错误。展开与收起使用共享动效令牌，减少动态效果时无动画。多个帖子草稿互不覆盖；收起与切换微博账号保留文本，发送捕获账号和正文快照，失败保留，成功不清除更新的草稿；受限帖子禁止展开。普通互动继续使用独立互动路由。
6. **验收**：源码守卫锁定两页公共原语并禁止旧的 `NAlert`、`NSkeleton` 与私有重复字段结构；Playwright 覆盖未配置、来源失败、请求失败、正常空态、已有帖子和评论草稿，读取空态与页面边界、按钮尺寸、表单宽度及溢出指标。编辑栏展开后检查两行关系、全部预设可经横向滚动到达、28px预设及常规字重、96px以内正常面板、气泡截断但点击填入全文、输入与发送并列、320px 到 1440px 及 200% 文本无页面溢出，并确认键盘可操作、错误仍可见；同时锁定短帖行高、正文与动作的桌面并列/移动换行关系，以及完整正文未被裁切；验证追加不替换、跨批次去重、并发互斥、失败继续加载、短屏填充、空批次/末页停止、权限变化旧响应隔离、返回已加载批次与滚动恢复；保留无权限操作零请求断言，并运行前端测试、类型检查、真实组件预览和完整静态构建。

## 差异化应用概览

Team、Shop、Transaction 与平台 Admin 的概览采用深色工作台锚点、浅色数据区、清晰分隔和真实业务路径，沿用微博概览的科技感与公共前端库；不使用虚构趋势、完成率、在线状态或装饰动画。Chat 与微博原面板保持原样。

- Team 团队以实体、成员、文档、通知真实计数和组织/资料两组入口构成资源运行台；个人以当前身份、角色、字段与有效权限摘要组织资料入口。
- Shop 团队与个人以服务 → 权益包 → 卡活动 → 商品的配置路径为主，订单作为独立履约入口，并呈现当前身份与所属工作台摘要。只读取访问快照，不将入口数量冒充业务统计。应用级 `ShopOverviewWorkspace` 是两个工作台正文的唯一布局所有者：`personal` 与 `steps` 必填、`access` 可选；步骤结构复用公共 `LsDashboardPath` 契约，无插槽；组件内部组合配置路径、订单入口和身份范围，页面负责查询与路由数据，不穿透其样式。
- Transaction 团队以流水核对与权益/余额两条业务线并排；个人以本人角色与业绩统计加接单、顾客、权益入口呈现，统计复用 `/personal/stats`，不增加实体筛选。
- Admin 以平台指标、资源检索、近期资源和治理事件形成监管面板。

页面拥有分组布局，公共组件拥有内部视觉。所有真实异步摘要保留加载、错误与受限占位，不能把未获取数据显示成 0。概览入口始终可用；宽屏可并列，窄屏按阅读顺序堆叠，在 320—1440px 与 200% 文字下无横向溢出。组件契约与 DOM 几何测试验证这些边界。

### 新增成员的可选入职代填

`/member-add` 的“新增成员”任务包含个人入队码、默认关闭的 `LsSwitchField` 代填开关及可选入职字段，共用一次提交。关闭代填不提交残留草稿，也不受必填字段或表单读取失败阻塞；开启后校验必填项，加载、失败、上传或提交期间阻止提交。字段读取失败可通过关闭后重新开启代填恢复；无字段时使用统一的 `LsEmptyState` 展示空状态并提示可以直接添加成员，需要收集资料时先配置普通入职字段。表单由 `LsPanel` 承载，内部使用 `NFlex` 和 `LsField`，加载使用 `LsAsyncState`，操作区使用 `LsFormActions`，不保留私有操作栏 CSS。草稿纳入离开保护，查询刷新不得覆盖输入，提交期间锁定字段。

自行申请与代填均不提供固定“补充说明”输入，不提交 `memo`；额外资料由团队配置普通入职字段收集。历史申请仅在已有说明时展示。

`JoinApplicationFields` 是自行申请和管理员代填的唯一字段视觉所有者，参数仅含 `fields/modelValue/uploadFile/uploadDisabledReason/disabled`，事件为值更新及上传状态；统一处理文本、选项、日期、文件和上传错误。两个页面只编排请求与提交，不保留重复字段 DOM/CSS。沿用动态加入字段的 Naive UI 复选组具名例外（不使用普通设置复选组）；该例外从 `JoinView` 迁移到此组件，收敛动态字段控件后撤销。桌面、移动端保持字段顺序、可访问标签、选项换行和 44px 触控区，父级不得穿透。由 `tests/member-join-code.spec.ts`、前端源码守卫和组件预览验证。

成员新增/编辑的主操作保留在标准页头文档流中，移动端不得另建覆盖工作台底部导航的固定操作栏；浏览器断言提交按钮底边不超过底部导航顶边，并使用真实点击验证。
