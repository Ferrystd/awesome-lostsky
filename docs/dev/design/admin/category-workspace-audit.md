# 复用现有分类工作区：Team 审计样板

实施状态：审计样板已完成真实代码预览；用户随后明确授权将同一现有工作区用于其他适用页面，本轮增加 Team 角色权限和 Admin 平台角色创建/编辑。待用户检阅及主对话集中验收。不开发新模板、不重构共享外壳。

## 现有工作区复用与视觉归属

分类工作区用于“先选稳定范围，再处理内容”。本轮只把 Team `/audit` 作为新增样板；`/settings`、`/notices/sent` 是保留原样的视觉基准。有真实稳定分类才显示分类栏，不给普通列表制造分类。事件流、表单与表格只是右侧内容形式。

当前明确适用的现有页面：

| 页面 | 应用 / 路由 | 稳定范围 |
| --- | --- | --- |
| 团队设置 | Team `/settings` | 业务应用分类 |
| 通知中心 | Team `/notices/team`、`/notices/sent` | 团队通知与已发送范围 |
| 角色权限 | Team `/roles/:id` | 同一角色下的业务权限分类 |
| 平台角色创建 / 编辑 | Admin `/roles/new`、`/roles/:id` | 同一平台角色下的权限分组 |
| 审计日志 | Team `/audit` | 产生事件的应用 |

本次扩展仅限上表角色页面，设置和通知黄金页保持原样。顾客、成员、商品、文档与角色列表属于对象目录；对象详情、普通编辑、人员角色分配、个人资料及总览分析不因已有组件名或少量筛选项而归入分类工作区。

直接组合黄金页已有的 `AdminPageHeader + TeamCategoryLayout`，分类只传现有 `items/current/label` 并响应 `select`，不新增公共参数或模板组件。页面沿用黄金页的页头到主体 24px 间距；`TeamCategoryLayout` 原样持有 184px 分类列、24px 列距、桌面 20px / 手机 12px 内衬，以及内容容器不足 768px 时的选择器。不修改 `TeamCategoryLayout`、`TeamCategoryNavigation`、`LsCategoryPage` 或黄金页面。共享场景、材质与暂停控制保持原有实现，页面不再包一层装饰卡片，不穿透公共组件内部。此前审计页调用的既有 `LsCategoryPage` 包装已换为这组黄金页直接组合；没有新建或撤销公共模板文件。

## 信息与操作位置

- **主要信息**：按日期分组的连续事件；每条以动作、目标资源和标识为主。日期只分组当前服务端分页的相邻记录，不重排、不合并跨页日期、不附加日期统计。
- **次要信息**：执行人、时分秒和应用名，允许长内容自然换行。沿用服务端 `action_label/resource_label/application_label` 以及 `actorLabel`，不新增业务字典或未知动作解释。
- **操作位置**：左侧应用分类来自 `/audit/catalog` 的 applications，并包含“全部应用”；右侧首行是 `LsListToolbar embedded` 的搜索与更多筛选，数量为弱文字。展开后保留动作、资源、完整时间范围筛选。整条事件是可聚焦的详情链接，末端显示图标与“查看详情”；请求 ID 和完整上下文继续在既有 `/audit/:id` 展示。页头没有额外跳转入口。

`TeamAuditEventStream` 是审计业务区块，唯一负责事件分组、行内容、轻分隔与窄屏换行；不扩展为跨应用万能列表。页面只负责请求、权限、筛选、状态与分页。`/audit/index`、query key、查询参数、20 条分页、`team.audit.read` 与现有详情路由不变；搜索仍支持执行人、动作、资源及请求 ID。原列表到详情没有附带 query，本次沿用该路径。

## 状态与适配

Team `/audit` 的日期标题由 `TeamAuditEventStream` 持有吸顶样式：仅在所属日期分组范围内使用 `position: sticky; top: 0`，下一组自然顶替，不叠加多层日期，不固定分类与搜索栏。当前工作台顶栏随文档滚动，不额外预留顶栏空隙。日期标题平时为无底色文字；仅吸顶后以贴近页面的 `--cloud` 不透明底色包住日期，宽度随文字、小圆角、无阴影和描边，不形成整列色带。文字始终与事件左边缘对齐，底色切换不改变尺寸，列表首行保留分隔线。`IntersectionObserver` 同时观察每组顶部的隐藏锚点与日期标题，支持快速跳过锚点的滚动，回滚后恢复透明，切换数据与卸载时断开旧观察；不新增滚动监听。桌面、移动端及文字放大保持自然高度和原有 h2 语义，不复制标题、不增加动画；事件详情链接预留日期条高度的滚动间距以保护键盘焦点。加载、失败、空与受限时不存在事件流，因此不显示吸顶日期。无新增例外。验收覆盖同组吸顶、跨日顶替、列表末尾释放、窄屏无横溢及键盘聚焦。

日期吸顶的定向验收命令为 `npm run test:e2e -- tests/team-audit-sticky.spec.ts --project=desktop-chromium`；用例显式覆盖 320、375、768、1024、1440px 和 375px 下 200% 文字放大，使用模拟接口，不读取生产数据。

页头与分类不随主查询切换状态。加载、错误、空与受限状态留在右侧正文，复用 `LsAsyncState/LsEmptyState`；筛选目录加载与失败另行在正文提示，避免伪装为没有应用。受限时不读取 API、不展示缓存事件或分页。主查询成功后才显示数量与分页。

事件行没有固定请求 ID 列、不截断长执行人/动作/资源标识；详情可查看完整值。右侧容器不足 32rem 时事件详情入口换行、高级筛选单列。分页保持 `NPagination`，最多五个页码槽位，极窄尺寸允许局部分页区滚动。键盘焦点沿用公共分类组件，事件链接使用可见焦点；不新增动画。无新增权限或视觉参数例外。
