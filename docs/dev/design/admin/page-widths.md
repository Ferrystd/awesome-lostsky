# 后台页面宽度规范

页面宽度按用户当前任务选择，不按应用名称、接口、组件名或屏幕空白决定。实现唯一入口是路由 `meta.pageWidth` 与 `LsPage`；Team 全部工作台路由必须显式声明，其他应用改动页面时遵守本规范。标准值不得由页面自行调整。

| 类型 | 标准 | 适用内容 |
| --- | --- | --- |
| `form` | `42rem`，默认字号下 672px | 新建、编辑、设置等单列填写任务；普通个人资料 |
| `content` | `64rem`，默认字号下 1024px | 阅读与对象详情；包含资料、经营摘要、关联集合、权限分配的复合管理任务；富文本编辑器；包含分类导航的设置中心 |
| `wide` | `90rem`，默认字号下 1440px | 概览、仪表盘、可筛选集合、表格、文件与审计日志 |

上述值是最大可用内容宽度，实际宽度为该上限与壳层剩余空间的较小值。`rem` 随用户字号缩放，禁止用固定像素宽度抵消文本放大。不得因为路由含有 `detail` 或 `edit` 就机械归类；复合管理详情可用 `content`，纯编辑任务用 `form`。

## 边界与对齐

- `LsPage` 负责整体居中及唯一页面限宽；壳层只扣除侧栏并提供页面边距，不再用另一层 `max-width` 缩小页面。
- 页面标题、说明、工具栏、主内容与页级操作共用同一个页面边界。页内不得再放任意限宽容器，制造标题宽、表单窄、保存动作悬空的布局。
- 面板内的字段和组级保存动作使用该面板的同一内容边界。每组仅一个保存动作，置于字段末尾；反馈紧邻动作并指明所属分组。
- Team 壳层在 900px 以下提供左右各 `1rem` 边距，在 900px 起提供各 `1.5rem` 边距；侧栏占用的空间先扣除。三档容器均可向下收缩，320px 不得横向溢出。
- 窄屏字段与复杂选项自然换行，普通表单默认单列，组末按钮按 `LsFormActions` 在 640px 以下满宽。宽数据表可在自身容器内横向滚动，不得拉宽整个页面。
- 长文正文可保留阅读行长子区域；这不是第四种页面宽度，不能改变页头、正文面板和页级操作的外边界。

## 例外管理

例外必须在应用规范具名记录路由、子区域、数值、用户任务理由、失效条件及验证方法。先由前端审查确认任务确实不适合已有三档，再修改实现与对应测试；不需要为已有规范内的常规选择额外询问用户。未登记的页内限宽不允许新增。

Team 已有例外与逐路由映射见 [Team 页面宽度审计](team-page-widths.md)。规范验证需要路由枚举守卫和真实 DOM 尺寸；至少检查 320、375、768、1024、1440px、足以达到 1440px 内容上限的宽桌面，以及 200% 文本放大。

## Team 设置组实现

设置与通知的分类布局由同一 `TeamCategoryLayout` 和 `TeamCategoryNavigation` 实现，留在 Team 应用内。布局只有语义分类数据、当前值、可访问名称和内容插槽，不接受 width/layout/compact 等视觉参数；面板表面由各自内容组件持有。通知与设置均使用 content 容器。导航项提供 `to` 时渲染真实 RouterLink，未提供时渲染控制当前编辑组的按钮；移动选择分别导航或发出 select 事件。方向键在链接之间只移动焦点，Enter 保留原生导航语义；设置按钮延续方向键切组并聚焦。通知具体 query 与返回规则见 [Team 应用](../../apps/team.md#通知中心与地址状态)。

用户指定的具名视觉例外：仅 `/settings`、`/notices/team` 和 `/notices/sent` 使用暗底流动极光。Team 应用根既有 `NConfigProvider` 按精确路由选择 `darkTheme`、`lostskyAuroraTheme` 和 `ls-theme-aurora` 语义令牌；离开上述路径即恢复默认浅色主题。详情、发送页、个人收件箱和其他应用不启用该主题。页头、导航、表单与通知均沿用现有组件读取语义令牌（主操作文字使用 `--on-primary`，浅色默认白、暗场景深墨色），不允许调用方穿透其内部样式。Team 壳层自身表面使用 `--surface`，保持默认浅色等价。

`TeamScene` 在既有暗色路由作用域内持有可视区域背景和暂停状态，覆盖页头、内容和滚动后的留白，不贡献布局高度；`TeamCategoryLayout` 复用注入状态将暂停控制放在分类下方。`TeamAuroraBackdrop` 与自写 `aurora-renderer.ts` 绘制大范围青绿、冰蓝和深色连续光场。鼠标事件只缓存归一化坐标，bounds 在 resize/scroll 更新；24fps 插值牵引中心与形变，离开缓归、触屏仅自主流动。暂停及减少动态冻结画面，失败时保留多层静态渐变。工作台页头显式保持在背景上方。

两页共用设置模板：1024px 上限、184px 分类列、24px 列间距、桌面20px/手机12px 内衬、页头到主体24px。`TeamPageLink` 为团队能力和发送通知提供同款图标文字轻入口。暗场景面板使用轻透冷墨渐变、细内高光和柔影，文字区域保持高遮蔽；材质令牌默认不影响其他页面。通知 `LsListToolbar` 显式 embedded 模式去掉外卡片，保留标准搜索及选择器，手机搜索独占首行、筛选/次操作自然换行；默认模式保持。

背景不可聚焦且 `aria-hidden/pointer-events:none`，不得挡住焦点和控件。现有 `LsButton` 提供暂停/播放，系统减少动态时自动显示静帧并隐藏该控制。隐藏或离屏停止连续绘制；卸载取消动画、解除观察器与事件、释放GPU资源；WebGL不可用或上下文丢失时显示CSS静态回退，业务内容与操作保持可用。帧率上限24fps，canvas限制为可视区域高度和约26万像素，手机不提高像素倍率，不按长列表scrollHeight分配。所有加载、权限、禁用、失败与草稿行为保持原契约。

动效方向参考 [React Bits Aurora](https://reactbits.dev/backgrounds/aurora)，视觉为用户指定的大范围渐变光影。实现为本项目自写WebGL解析曲线算法，没有复制其源码或引入依赖。验收覆盖实际画面随时间变化、暂停/恢复、减少动态、离屏/隐藏/卸载、无WebGL回退、路由主题恢复，以及两页320—1920px、200%文本和导航对比度。实际运行页可记录短视频；组件预览仍为人类专用PNG。

`/settings` 使用 `content`：用户需要在多个业务分类间切换并保留草稿。`TeamCategoryLayout` 排列分类导航和当前编辑区，背景由外层 `TeamScene` 持有；`TeamSettingsGroup` 持有右侧唯一编辑表面。容器扣除内边距后的可用宽度达到 `48rem` 时，导航轨为 `11.5rem`（默认字号 184px），编辑轨占剩余空间；不足时切为顶部分类选择器。标题和设置中心共用 64rem 页面边界，字段与保存操作在右侧表面内对齐。禁止为大屏增加巨型标题或重复卡片。

`TeamCategoryNavigation` 的 `items/current/panelId` 表达分类、未保存标记、选中值与受控区域，`select(key)` 仅通知页面切换。分类按 schema 业务顺序呈现，包括未知业务组；桌面原生按钮支持 Tab、Enter 和方向键，移动端使用现有选择器。schema 刷新保持仍有效的分类，移除时回到第一有效分类。所有草稿由页面保管；切换不保存、不丢弃，不新增自动保存或本地持久化。保存中允许继续编辑、切换分类，整页防止重复提交，结果仅归属提交组；成功仅确认提交快照。刷新与离开保护检查全部分类草稿。

具名原生控件例外：`TeamCategoryNavigation` 分类按钮属于具有 `aria-current/aria-controls` 的页内导航，保留原生按钮与组件自己的导航焦点/选中规则，不复用提交动作皮肤；例外只限此组件，不授权页面自由创建普通按钮。团队能力是次级路由链接，不属于页头主提交动作。

`TeamSettingsGroup` 是 Team 专属业务组件：`app/values` 表达设置 schema 和当前草稿，`loading/disabled/saved/error/restricted` 表达保存与权限状态，`update(key,value)` 和 `submit` 交还页面处理。禁止增加布局/宽度参数。保留原整数校验、可空数值、能力禁用说明和整组保存 API；成功只确认提交快照，较新的草稿仍显示未保存状态。原生 form 作为独立原子提交边界，按组件化规范允许自身面板边界，不嵌套同义面板。真实组件预览覆盖默认、选中、禁用、加载、失败和移动状态。

`LsWorkspaceHeader` 在上述暗场景使用语义 `contextual` 模式，正文保留唯一主标题；其他页面继续默认标题模式。暗主题 radio 未选与悬停采用中性令牌，选中才使用青绿；滚动条和分隔线使用低强调中性色。

通知保留左分类与右列表，与设置完全共用上述间距模板，不启用顶端横向标签。TeamNoticeRow 保留紧凑行、无正文省略和长文自然换行。工具栏与列表间距16px；个人收件箱不受嵌入工具栏及材质影响。
