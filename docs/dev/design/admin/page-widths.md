# 后台页面宽度规范

页面宽度按用户当前任务选择，不按应用名称、接口、组件名或屏幕空白决定。实现唯一入口是路由 `meta.pageWidth` 与 `LsPage`；Team 全部工作台路由必须显式声明，其他应用改动页面时遵守本规范。标准值不得由页面自行调整。

| 类型 | 标准 | 适用内容 |
| --- | --- | --- |
| `form` | `42rem`，默认字号下 672px | 新建、编辑、设置等单列填写任务；普通个人资料 |
| `content` | `64rem`，默认字号下 1024px | 阅读与对象详情；包含资料、经营摘要、关联集合、权限分配的复合管理任务；富文本编辑器；包含分类导航的设置中心 |
| `wide` | `90rem`，默认字号下 1440px | 概览、仪表盘、可筛选集合、表格、文件与审计日志 |

上述值是最大可用内容宽度，实际宽度为该上限与壳层剩余空间的较小值。`rem` 随用户字号缩放，禁止用固定像素宽度抵消文本放大。不得因为路由含有 `detail` 或 `edit` 就机械归类；复合管理详情可用 `content`，纯编辑任务用 `form`。

## 边界与对齐

- `LsPage` 负责整体居中及唯一页面限宽；壳层只扣除侧栏并提供页面边距，不再用另一层 `max-width` 缩小页面。
- 页面标题、说明、工具栏、主内容与页级操作共用同一个页面边界。页内不得再放任意限宽容器，制造标题宽、表单窄、保存动作悬空的布局。
- 面板内的字段和组级保存动作使用该面板的同一内容边界。每组仅一个保存动作，置于字段末尾；反馈紧邻动作并指明所属分组。
- Team 壳层在 900px 以下提供左右各 `1rem` 边距，在 900px 起提供各 `1.5rem` 边距；侧栏占用的空间先扣除。三档容器均可向下收缩，320px 不得横向溢出。
- 窄屏字段与复杂选项自然换行，普通表单默认单列，组末按钮按 `LsFormActions` 在 640px 以下满宽。宽数据表可在自身容器内横向滚动，不得拉宽整个页面。
- 长文正文可保留阅读行长子区域；这不是第四种页面宽度，不能改变页头、正文面板和页级操作的外边界。

## 例外管理

例外必须在应用规范具名记录路由、子区域、数值、用户任务理由、失效条件及验证方法。先由前端审查确认任务确实不适合已有三档，再修改实现与对应测试；不需要为已有规范内的常规选择额外询问用户。未登记的页内限宽不允许新增。

Team 已有例外与逐路由映射见 [Team 页面宽度审计](team-page-widths.md)。规范验证需要路由枚举守卫和真实 DOM 尺寸；至少检查 320、375、768、1024、1440px、足以达到 1440px 内容上限的宽桌面，以及 200% 文本放大。

## Team 设置组实现

设置与通知的分类布局由同一 `TeamCategoryLayout` 和 `TeamCategoryNavigation` 实现，留在 Team 应用内。布局只有语义分类数据、当前值、可访问名称和内容插槽，不接受 width/layout/compact 等视觉参数；面板表面由各自内容组件持有。通知使用 wide 容器，设置使用 content 容器。导航项提供 `to` 时渲染真实 RouterLink，未提供时渲染控制当前编辑组的按钮；移动选择分别导航或发出 select 事件。方向键在链接之间只移动焦点，Enter 保留原生导航语义；设置按钮延续方向键切组并聚焦。通知具体 query 与返回规则见 [Team 应用](../../apps/team.md#通知中心与地址状态)。

用户指定的具名视觉例外：仅设置页和通知中心的 `TeamCategoryLayout` 背景允许极淡静态青绿极光，由布局唯一持有两个低浓度 primary 光带（6%/4%）。不透明白色编辑面板、工具栏与列表保持原样；不改变页头/侧栏，不增加视觉参数、图片、动画或 blur 滤镜。伪元素限定在布局边界内、pointer-events:none，不裁切焦点；不得据此扩展为全后台装饰背景。验收包括两页响应式无溢出和导航对比度。

`/settings` 使用 `content`：用户需要在多个业务分类间切换并保留草稿。`TeamCategoryLayout` 只排列分类导航和当前编辑区，透明且不持有面板样式；`TeamSettingsGroup` 持有右侧唯一编辑表面。容器可用宽度达到 `48rem` 时，导航轨为 `11.5rem`（默认字号 184px），编辑轨占剩余空间；不足时切为顶部分类选择器。标题和设置中心共用 64rem 页面边界，字段与保存操作在右侧表面内对齐。禁止为大屏增加巨型标题或重复卡片。

`TeamCategoryNavigation` 的 `items/current/panelId` 表达分类、未保存标记、选中值与受控区域，`select(key)` 仅通知页面切换。分类按 schema 业务顺序呈现，包括未知业务组；桌面原生按钮支持 Tab、Enter 和方向键，移动端使用现有选择器。schema 刷新保持仍有效的分类，移除时回到第一有效分类。所有草稿由页面保管；切换不保存、不丢弃，不新增自动保存或本地持久化。保存中允许继续编辑、切换分类，整页防止重复提交，结果仅归属提交组；成功仅确认提交快照。刷新与离开保护检查全部分类草稿。

具名原生控件例外：`TeamCategoryNavigation` 分类按钮属于具有 `aria-current/aria-controls` 的页内导航，保留原生按钮与组件自己的导航焦点/选中规则，不复用提交动作皮肤；例外只限此组件，不授权页面自由创建普通按钮。团队能力是次级路由链接，不属于页头主提交动作。

`TeamSettingsGroup` 是 Team 专属业务组件：`app/values` 表达设置 schema 和当前草稿，`loading/disabled/saved/error/restricted` 表达保存与权限状态，`update(key,value)` 和 `submit` 交还页面处理。禁止增加布局/宽度参数。保留原整数校验、可空数值、能力禁用说明和整组保存 API；成功只确认提交快照，较新的草稿仍显示未保存状态。原生 form 作为独立原子提交边界，按组件化规范允许自身面板边界，不嵌套同义面板。真实组件预览覆盖默认、选中、禁用、加载、失败和移动状态。
