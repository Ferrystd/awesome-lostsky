# 后台页面模式

页面结构的抽象阈值、职责边界和迁移流程统一见[后台页面组件化方法](componentization.md)。本页只定义已经成立的页面模式。

父子页面归属、独立任务返回与 URL query 预填统一遵循[前端路由与页面间导航](../../architecture/frontend-navigation.md)，不由单页自行约定。

## 顶栏与页面标题

页面类型对应的三档尺寸、边距和对齐统一遵守[后台页面宽度规范](page-widths.md)，不得在视图里再任意限制主内容宽度。

`team`、`shop manage`、`transaction`、`weibo`、`admin` 使用同一 `LsWorkspaceHeader`。团队应用壳层在桌面 `actions` 插槽直显团队、商品、记账、聊天、社区和微博六入口；移动端统一复用 `LsAppSwitcher`，禁止另建应用选择器或个人/团队分段控件。团队模式从既有概览或主页面进入个人工作台，个人模式由顶栏当前应用返回团队模式。桌面动作必须为图标加文字；移动端应用入口使用“应用”面板，其他业务命令仍进入带文字的“操作”菜单。认证和会话应用可保留专属壳层，Chat 只提供相同的应用切换、不提供模式切换。页面内容使用 `LsPage` 和 `LsPageHeader`，不得复制不同高度、字号或返回样式。

`LsPageHeader` 在可用容器宽度不足 `16rem`（包括放大文字后）时，将动作排列到标题和说明下方，避免固定宽度主操作挤出页面；正常容量保持既有左右布局。适配由公共标题组件的容器查询负责，调用方不得穿透或传视觉参数。通过添加成员页的 320px、200% 文字及按钮边界断言验证。

## 搜索、筛选与集合页

可定位集合页必须使用 `LsListToolbar`，包括 Team 的实体、成员、顾客、文件、文档、角色、虚拟实体、通知、加入审核，Transaction 的流水、绑定、顾客余额，Admin 的用户、团队、管理员、角色、审计。

- 搜索始终存在，图标在输入内；只有明确帮助缩小范围的筛选才紧随搜索。
- 桌面工具栏采用 40px 紧凑控件，搜索最大 28rem、普通筛选 10rem；筛选必须保留完整边框、文字和箭头，不得折叠成竖线或让选择箭头看似进入搜索框。移动端改为 44px 并逐项满宽排列。
- 结果数量在末端，使用 aria-live；分页不是结果数量的替代品。
- 可用宽度不足时，工具栏与筛选组自然换行；搜索和单项筛选的最小宽度不得超过父容器，包括 200% 文本放大后的中间屏幕尺寸。规则由 `LsListToolbar` 持有，页面不得覆盖。
- 移动端顺序固定为搜索、筛选、动作、数量，均占可用宽度。
- 连续数据使用 `.ls-list` 或表格容器及细分隔线；通知、审核、主体目录不得逐项做悬浮卡片。
- 列表 hover/focus 只使用表面色或可见焦点环，不改变边框粗细、不位移。

## 主体、状态与动作

主体统一用 `LsEntityIdentity`：真实头像优先；无图时按类型图标或首字回退；媒体位始终是圆角方形，同时显示类型、名称和 slug。直接描述该主体的状态使用组件 `status` 插槽紧随名称，不能作为独立网格列漂到整行末端；表格中用于跨行比较的状态才保留独立状态列。状态统一用 `NTag`，不得用页面私有胶囊。

列表行和主体卡片的桌面入口使用透明、无边框的图标加文字，不使用主色填充、浅色底或圆角按钮气泡；hover/pressed 只改变文字或图标状态，不形成新的胶囊轮廓。移动端仍采用“一个安全主操作 + 更多”，两者同样保持图标加文字的轻量入口外观和至少 44px 触控区。查看/管理通常是主操作，封禁、移出、删除不得成为移动端主操作。页面入口不因 Permission 或 Ability 禁用；进入目标页后按列表或普通数据规则降级。表单提交、创建、确认和破坏性确认属于命令按钮，缺少条件时使用可点击说明的公共权限态。

角色权限中的实体选择只提供实体管理或身份委托 Permission 的目标上下文，必须放在对应折叠组内、位于指定实体项之前，选择实体本身不得直接增删 Permission。通用权限和指定实体 Permission 使用同一级折叠分组与相同复选框样式；指定实体项必须先选择当前团队实体，再勾选适用项。当前团队目标使用团队实体选项接口，不得复用会受全局搜索可见性限制的跨团队搜索接口；聊天使用当前 Entity，虚拟人员通过身份委托切换，覆盖冗余仅在前端提交时清理。

页面主内容或主集合的空数据和筛选无结果必须使用 `LsEmptyState`，传入 `title` 与 `description`，查询驱动区域另传原始查询结果 `source`；局部已知授权限制传 `accessReason`：标题说明当前没有什么，说明文本给出来源、边界或下一步；不得直接拼装裸图标、标题和段落，不得为单页扩展图标、动作、尺寸或样式参数。组件固定为白色有边界面板、Naive `NEmpty` 图标与居中排版，标准最小高度为 `12rem`、上下内边距为 `2rem`；禁止用 `vw` 或页面私有样式随桌面宽度继续拉高，仅在文案换行或文本放大确实需要时自然增高。桌面和移动端均须自然换行且不得横向溢出。创建等主操作保留在页面标题，不塞入空状态。消息时间线、详情卡片、表单候选区和统计小卡等局部区域不是“页面无数据”，继续使用与所在区域密度一致的紧凑说明；如需偏离，必须在应用规则登记原因。

同一顶栏中的链接、路由入口和 Naive UI 按钮使用完全相同的 `--font-ui`、14px 字号和 600 字重。`NDropdown` 等无根组件必须由真实 DOM 容器承担响应式显示类；验收时桌面不得同时出现完整动作和移动端“操作”按钮。

## 表单、上传与分页

查看、创建、编辑和审核使用可刷新、可返回、可直接分享的独立任务路由。列表只承担定位、概览和进入任务，不常驻主从编辑器；弹层只承载简短、低风险的单步输入或确认。

设置控件按数据语义选择：布尔值使用公共开关，2–3 个需要比较含义的互斥选项使用带标题与说明的单选卡，更多或无需解释的选项使用下拉框；不得直接展示枚举 case name。移动端默认单列，宽屏只有在任务关系明确时增强布局，不为填满宽度并排普通文本输入。

表单默认单列，宽度不超过 `form` 容器；普通单控件字段必须使用 `LsField`，复杂联动、校验组或 Naive 表单验证使用 `NFormItem`，不得保留页面级 `.field` 标签皮肤。表单与局部操作错误使用只接收 `message` 的 `LsInlineError`；页面级异步加载和真实错误使用 `LsAsyncState`，两者不得互换或重复报告。同组提交与取消按钮同高度、同视觉层级，宽度由 `LsFormActions` 按文案自适应，并通过 `LsButton` 的 `icon` 插槽承载图标。上传必须使用 `LsUploadField`，固定宽度只属于上传组件内部，不扩散为全局命令宽度。分页使用 `NPagination`；确需上一页/下一页模式时使用同尺寸 `LsButton`。

有边界的独立内容区统一使用无视觉参数的 `LsPanel`，标题、正文和页脚分别进入对应插槽；页面不得重新声明 `.panel` 的圆角、边框或内边距。连续表格、列表、弹层和确需不同语义根节点的表单不强行套用 `LsPanel`，但应使用 Naive UI 自有容器或公共列表边界。原生 `<table>` 只用于纯展示文档内容；后台数据表优先使用 `NDataTable`。Admin 用户、团队、管理员与审计页，以及 Transaction 流水、绑定、顾客余额与余额明细页，已满足三页以上相同的响应式需求，统一使用 `LsResponsiveDataTable`；Team 顾客、成员、文档与 Shop 后台商品目录使用[对象目录](object-directory.md)。其他新模式不得仅为包一层 DOM 建组件，必须在 Wiki 登记达到相同复用阈值。

## 例外与检查

Admin 平台命令搜索是应用专属能力，可保留快捷键和弹层，但输入、结果行、移动布局和状态遵守公共组件。检查：在 320、375、768、1024、1440px 分别确认标题、工具栏、列表边界、操作层级与无横向溢出。
