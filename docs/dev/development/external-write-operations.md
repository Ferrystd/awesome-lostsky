# 外部写操作与日志保留

外部写操作只保存足以定位结果的最小结构化数据：HTTP 状态、远程 code/message、归一化 reason、远程资源 ID、本地调度键与时间。微博操作还可保存截断后的正文摘要和媒体 ID 数组，用于审计和定位，不保存正文或完整远程响应。禁止保存授权头、Cookie、token、签名参数或其他凭据。无法确认的结果使用 `unknown`，不根据模糊文案猜测成功或失败。

微博及其他带本地操作日志的外部写入遵循以下流程：

1. 在本地事务内以唯一 `dispatch_key` 提交 `dispatching`；
2. 事务外发出最多一次远程写请求；
3. 只回写最小结构化结果；
4. 定时任务重投发现已有 `dispatching` 时，改为 `unknown` 且不重发远程写请求，并进入下一周期；不人工重放同一 `dispatch_key`。

微博操作日志默认只向 API 提供最近 30 天记录，`system:cleanup` 按 `config/cleanup.php` 的保留期和批次上限硬删除超期日志；超期且未被任务引用的微博媒体元数据也可在同一周期删除。OSS 删除补偿不因日志过期自动删除，失败任务会按可用时间重试并保留最后错误。资源有限时不通过保存完整响应“以备万一”。
