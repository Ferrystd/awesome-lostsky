# 测试须知

维护项与生成命令见[代码更新清单](checklist.md)。测试范围以本页规则为准。

## 范围判定

测试范围按当前任务实际修改的文件和契约判定，不按 `git status` 中整个工作区的差异判定。用户已有改动、前序任务改动和本次只读取或消费的文件必须保留，但默认不纳入当前任务的测试范围。

- 纯前端任务只选择前端测试、类型检查、按需 E2E 和静态构建；本次没有修改 PHP、路由、OpenAPI 或请求/响应契约时，不运行 `php -l`、`php tests/*`、`npm run test:backend` 或 OpenAPI 路由测试。
- 读取现有 OpenAPI、生成前端类型、消费既有接口，或发现工作区存在前序后端差异，都不构成运行后端测试的理由。
- PHP、路由、OpenAPI 或后端行为测试只由当前任务对对应层的实际修改触发。前端失败只有在错误证据明确指向后端契约时，才可以扩大到直接相关的后端检查。
- 只有直接相关检查失败且证据指向其他层、当前任务实际跨层或修改了跨应用共享契约、用户明确要求全量回归，或进入发布验证时，才扩大测试范围。扩大前先说明具体风险、证据和准备执行的命令。
- 计划与交付记录应列出实际命令及其对应改动，不使用“相关 PHP/OpenAPI 测试”“必要时全量测试”等无法判定边界的表述。

满足范围条件后，先列出本次改变的行为、对应测试文件或用例，以及准备运行的命令。默认以文件路径和用例名称过滤，只运行受影响场景及适用的桌面/移动端项目；同一行为已有覆盖时不额外运行同义用例。扩大前说明新增范围与原因，不把整份大型测试文件、整个应用或全仓测试当作小改动的默认范围。

从下表选择覆盖当前改动的最小非重叠命令集。类型检查与静态构建是独立检查，不用全量测试替代；前端完整静态发布构建仍按[前端约定](frontend.md)执行。

| 改动 | 测试 |
| --- | --- |
| PHP | `php -l <文件>`、直接相关 PHP 测试 |
| 路由、OpenAPI、后端行为 | 相关测试；全量回归使用 `npm run test:backend` |
| 前端逻辑 | `npm test -- <受影响测试文件> -t <用例名称>`、`npm run typecheck`；跨应用共享契约或发布回归才运行不带过滤的 `npm test` |
| 页面、路由、登录 | `npm run test:e2e -- <受影响规格文件> -g <用例名称>`、`npm run build`；跨应用导航/登录契约或发布回归才运行不带过滤的 `npm run test:e2e` |
| 媒体、CORS | `npm run check:media`、`npm run check:cors` |
| 文档站导航、链接、元数据、模板、主题、生成字典或发布验证 | `npm run build:docs` |

纯文档维护（包括设计规范文字）不触发前端或后端业务测试；只有对应源码或契约也被本次修改时才加入相应检查。普通规则或正文文字修改先检查差异，不因文件位于 `docs/dev/` 就运行 `npm run build:docs`；只有上表所列站点契约受影响或准备发布文档站时才构建。文档构建含字典只读检查与双站严格构建；遇到不属于当前授权范围的人工手册错误时，按[构建失败与维护边界](wiki.md#build-failure-boundaries)记录阻塞，不能以补充检查代称完整构建通过。

## 组件封闭契约测试

涉及后台公共组件、已登记业务组件或页面结构时，测试必须执行[封闭组件契约](../design/admin/componentization.md#closed-component-contract)的自动守卫，不能只依赖 Wiki 阅读或组件截图：

- 静态源码契约禁止页面与未登记组件使用 `:deep(.ls-*)`、视觉 props、样式透传或公共组件私有类名；合法第三方边界只使用精确文件与精确模式白名单。
- 公共组件 props、emits、slots 和默认值通过精确快照、源码解析或 AST 检查锁定；新增入口必须与已更新的公共组件契约和真实变体测试同时出现。
- 交互断言与文案断言分开：新增交互测试时先确定要保护的用户行为和可观察结果，再选择定位方式。文案不是本次明确约定的产品契约时，不得仅凭按钮等控件的精确文字定位或判断交互成功；应在具体业务对象范围内定位操作，验证状态变化、提交载荷和反馈。文案本身属于需求时单独断言。测试与页面文字不一致时，先核对当前需求和改动归属，不得仅为通过旧断言而恢复文案。
- 等宽、满宽、容器最大宽度、响应式换行和横向溢出使用浏览器计算样式、元素边界或滚动尺寸断言；不得用截图像素比较代替。直接相关用例至少覆盖桌面与移动端，存在长文案、加载、禁用或只读状态时同步覆盖。
- 用户截图或真实页面视觉验收发现布局缺陷时，测试必须锁定截图所暴露的具体关系，而不是只断言页面存在或外层字段顶部：例如提示文字导致控件错位时读取控件轨道顶部，操作区挤压内容时比较两者边界，列宽不一时比较每个实际控件宽度。组件预览 PNG 仍不得作为像素基线。
- 测试发现调用方穿透时，修复视觉所有者并删除覆盖；不得通过扩大白名单、放宽选择器或把内部样式改成新参数来让测试通过，除非已经满足 Wiki 的参数准入或具名例外条件。
- 数字输入测试必须实际清空 `NInputNumber`，验证保存被阻止、页面不抛异常且恢复合法数值后可提交；金额动作同时断言顾客端预览与提交载荷一致。创建对象后紧接着从其他表单选择它的 E2E 必须在同一流程执行，防止候选缓存陈旧。
- 主数据和局部候选查询分别模拟失败；测试应区分“请求失败”和“合法空结果”，并验证错误区域、禁用动作与恢复路径。

## 执行去重与输出控制

- 同一份源码状态下，每条成功命令只运行一次；只有该命令覆盖的源码后来改变、上次失败或用户明确要求复验时才重跑。文档、Changelog 或构建产物的后续变化不触发已通过的源码测试。
- 跨任务集成可复用验证，但须记录原提交、命令与结果，并比较受测源码、测试、依赖锁、别名及构建配置；仅提交 SHA 不同不意味着必须重跑，文件未变也不足以忽略运行环境差异。合并后优先验证交叠区块及新组合的契约，有影响的输入发生变化才重跑对应检查。
- “基线已有失败”必须有同因证据：记录基线提交、等价依赖和配置、失败命令/退出码与关键诊断，区分真实同因错误与快照缺文件等环境噪音。分应用类型检查、部分目录检查或单站构建只能证明各自范围，不能替代失败的全量门禁；不排除业务文件、删除断言或降低 strict 来消除失败。
- 纯重构先固定既有可观察行为，再在修改后运行相同断言。业务契约确实改变时同步调整对应断言与依据；不得只刷新快照或哈希使其通过。删除旧页面时将仍有效的权限、请求载荷、金额空值和草稿保护断言迁到现行入口，不把删测试当作删旧功能的完成证据。
- 先运行定向测试；已通过的定向用例不因后续扩大范围而单独重跑。若已决定执行覆盖目标的全量命令，直接运行全量命令，不预跑相同用例。`git diff --check` 只在最终差异稳定后运行一次。
- 长命令运行中不重复启动；需要轮询时以约 60 秒为间隔，命令提前结束则立即处理，不为进度播报增加轮询回合。
- 成功结果只保留退出码、通过数量和耗时摘要；失败时只读取相关错误与必要日志尾部，不把完整成功日志反复送入上下文。
- 构建退出码为 0 且预期入口与资源目录存在，即完成构建验证。`www/` 中可再生产物受 `.gitignore` 管理，不以 Git 差异验收；除非任务明确涉及静态产物写入或加载错误，不再搜索、展开或逐行检查 `www/`、`dist/` 中的压缩文件。
- 交付前只做一次最终差异检查，不用重复读取源码、规范或已验证生成物代替测试证据。

## 数据库保护

数据库测试或补丁执行前：

1. 从根 `.env` 读取配置，不输出密码。
2. 核对库名和已有表，确认目标允许测试或迁移。
3. 执行后只读验证列、索引、外键、约束和迁移结果。

目标库已经核对清楚且用户已授权时，应继续执行补丁、fixture 和测试数据清理验证；数据库保护步骤不是默认跳过写入的理由。只有目标库仍不明确、疑似生产环境或缺少授权时才停止。

测试数据使用现有 fixture,推荐调用(生产环境慎用) [`service:call`](../operations/console.md)；写调用前先阅读服务实现。E2E 域名按[开发须知](development.md)配置。

## 前端 E2E 域名与就绪检查

`npm run test:e2e` 使用仓库内分组执行器：先由 Playwright 自动发现所有规格和桌面、移动项目，再按规格中声明的本地应用端口分组，逐组启动所需服务，以 1 个 worker 运行，等待该组服务退出后继续下一组。新增规格必须声明其应用 origin；无法匹配配置中的服务或发现 `test.only` 时直接失败，不静默遗漏。保留 `-- <规格文件> -g <名称>` 和 `--project` 过滤；自定义配置、分片、worker、reporter 或交互调试请直接使用 `npx playwright test`，不能用其局部结果替代完整发布门禁。

每次运行在忽略提交的 `test-results/e2e/<时间>/` 保存发现清单、各组 JSON 报告与 `manifest.json`。门禁逐项核对项目、文件、完整测试名称；遗漏、重复、意外新增、跳过、失败或重试后才通过均不算通过。某组失败后仍继续其余组，最终返回非零退出码，便于一次收集完整证据。此编排不修改断言、超时或重试策略。

这些浏览器用例的业务 API 全部使用显式 fixture，不代表真实后端集成通过。所有规格从 `tests/fixtures.ts` 导入测试入口；共享 context 阻断未模拟的 `/api` 请求及 API 域名请求，只报告 method、pathname，不记录令牌、查询串或请求体。`page.route` 的明确模拟优先，静态资源与 CORS 检查不受此兜底影响，Service Worker 被禁用以防绕过。执行器拒绝未使用共享入口、另建 BrowserContext 或直接使用 APIRequestContext 的规格；新增这类需求须先扩展隔离护栏，或放入独立的真实 HTTP 冒烟验收。真实 HTTP、数据库与外部服务验收须单独记录结果，不能与全模拟 E2E 混称。

Playwright 的开发服务器就绪地址必须使用 `127.0.0.1:<端口>`，不得依赖开发机 hosts、公共 DNS 或系统代理判断本地服务是否启动；浏览器进程通过 `--host-resolver-rules` 将测试所需的 LostSky 业务域名显式映射到 `127.0.0.1`。新增后台应用或测试子域名时，必须在同一变更中增加本地 webServer、浏览器映射和对应路由用例。桌面与移动项目使用相同映射；服务器启动失败属于测试基础设施失败，不得通过延长断言超时掩盖。

检查方法：在没有自定义 hosts 的环境运行 `npm run test:e2e`；就绪探测只访问 `127.0.0.1`，浏览器地址栏和请求仍保持真实业务域名，以继续覆盖 cookie、子域隔离和跨应用跳转。
