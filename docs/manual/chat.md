# 聊天

Chat 以当前实体身份参与团队会话。账号登录、团队选择和身份领取由 Account 负责；虚拟实体与 Webhook 的管理由 Team 负责。

## 功能基线

| 编号 | 用户目标 | 前置条件 | 应有结果 |
| --- | --- | --- | --- |
| CHAT-01 | 选择聊天团队 | 已登录 | 进入所选团队的聊天空间 |
| CHAT-02 | 查看已有会话 | 当前身份属于该团队且可使用 Chat | 只看到当前身份有权访问的会话 |
| CHAT-03 | 发起会话 | 对目标和会话类型具有访问权 | 创建或进入可用会话 |

## 使用流程

从 Chat 入口选择团队。若没有当前实体身份，或身份与所选团队不一致，按提示前往 Account 领取该团队身份，再返回原页面。

进入“消息”查看已有会话，使用“新会话”选择允许联系的对象。搜索有结果时显示匹配实体，没有结果时只显示无匹配提示。也可以从 Team 工作台顶栏或概览回到消息页；从实体、成员列表及详情进入时，新会话会预选对应对象，用户仍需确认自己的身份和会话设置。虚拟实体是否可参与、可被谁管理，由 Team 中的实体配置和权限共同决定。

Chat 顶栏的身份入口依据当前登录 JWT 跳转，而不是依据消息编辑器里临时选择的发送身份：客户进入 Shop“我的资料”，成员进入 Team“我的资料”，团队和虚拟实体进入 Account 身份选择。

## 当前边界

团队和会话参与者使用统一的主体识别样式，真实头像优先并保留类型、名称和 slug。Chat 保留会话专属布局；消息气泡是会话语义，不是后台卡片样式的通用例外。没有可用聊天团队时，团队选择页会显示统一的无数据面板；会话与消息区域仍使用适合聊天密度的局部提示。

- 登录账号本身不是聊天参与者，团队内会话必须使用有效实体身份。
- 切换团队不会自动把当前会话或权限带到另一个团队。
- Chat 不保存或修改客户资料；旧 `/profile` 只负责跳转到对应身份的管理入口。
- Webhook 令牌供外部集成使用，不可替代用户登录或实体身份。
