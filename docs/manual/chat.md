# 聊天

Chat 以当前实体(Entity)参与团队会话。账号登录、团队入口和 Entity 领取由 Account 负责；Team、成员与虚拟实体资料进入 Team 个人工作台，顾客资料进入商城顾客中心。Chat 保持单一消息工作台，不提供个人/团队模式切换。

## 功能基线

| 编号 | 用户目标 | 前置条件 | 应有结果 |
| --- | --- | --- | --- |
| CHAT-01 | 选择聊天团队 | 已登录，并在该团队具有成员或顾客关系 | 进入所选团队的 Chat 空间 |
| CHAT-02 | 查看已有会话 | 当前实体属于该团队且可使用至少一个参与身份 | 只看到当前实体或可操作虚拟实体参与的会话 |
| CHAT-03 | 创建单聊或群聊 | 可操作发送 Entity，并满足创建 Permission 或顾客策略 | 创建新会话，或进入已有普通单聊 |
| CHAT-04 | 创建临时会话 | 非 Customer 发送身份，且有 `chat.temporary.create` | 会话可设置到期时间并自动关闭 |
| CHAT-05 | 收发、编辑或撤回消息 | 发送 Entity 是有效参与者；操作窗口或审核 Permission 满足 | 消息状态同步到会话参与者 |
| CHAT-06 | 关闭会话 | 可操作会话创建 Entity，或有 `chat.group.manage` | 会话变为只读，不再允许发送 |

## 选择团队与身份

Chat 团队选择页汇总真实账号作为成员或顾客加入的团队。没有可用团队时，应先加入团队，或在对应 Shop 建立顾客关系。

选择团队后，当前实体必须属于该团队。缺少身份或团队不匹配时，系统会前往 Account 成员回调；确认后返回原页面，取消则保留原身份。

进入团队 Chat 后还有“以此身份发送”选择。候选包括：

- 当前有效 Team、成员或顾客 Entity；
- 当前实体通过具体或通配 `chat.virtual.<slug>.act` Permission 可以代表参与聊天的虚拟实体。

消息编辑器中临时选择的发送实体只影响本次会话行为，不替换登录 JWT 中的当前身份。

顶栏资料动作按 JWT 最终叶子实体进入 Team 个人工作台或商城顾客中心；Team 实体与成员、虚拟实体使用同一 Team 个人入口，不使用会话内临时发送者。

同一顶栏固定提供「团队、商品、记账、聊天、微博」应用切换：桌面端五项直接显示，移动端与 Team 一致收进「操作」菜单，不显示「切换应用」下拉按钮。Customer 仍能看到五项，其中「商品」进入商城顾客中心，「团队」「记账」和「微博」因顾客不进入后台工作台而禁用并说明原因。

## 查看已有会话

“消息”只列出当前实体直接参与，或当前实体有权操作的虚拟实体参与的会话。知道会话 UUID 也不能读取未参与的会话。

会话详情显示参与者、当前发送身份、临时会话到期时间和连接状态：

- **实时**：通过实时通道接收更新；
- **定时更新**：实时连接不可用时轮询新消息；
- **连接中**：正在建立或恢复连接。

连接方式变化不会扩大可见范围。网络恢复后仍按当前实体、参与关系和团队重新鉴权。

## 创建会话

从“新会话”选择发送 Entity、会话形式和参与者。

### 单聊

单聊必须且只能包含两个不同参与者。普通单聊在同一团队、同一对参与者之间保持唯一；重复创建时会进入已经存在的会话。临时单聊可以重复创建。

### 群聊

群聊至少包含两个参与者，可以填写最多 100 字的群聊名称。非 Customer Entity 创建普通会话需要 `chat.conversation.create`。

顾客是否能创建或加入群聊由团队设置决定：

| 顾客群聊模式 | 顾客结果 |
| --- | --- |
| 禁止顾客加入 | 顾客不能创建群聊，也不能被邀请 |
| 仅限团队邀请 | 顾客不能创建，只能由团队成员邀请 |
| 允许顾客创建 | 顾客可以创建群聊，但不能主动邀请其他 Customer |

群参与者后续增删需要 `chat.group.manage`，且群聊至少保留两个有效参与者。当前 Chat 页面以查看参与者为主，尚未提供完整的群参与者增删界面。

### 临时会话

开启“临时会话”后可以设置晚于当前时间的自动关闭时间，也可以不设置、之后手动关闭。创建者除 `chat.conversation.create` 外还需要 `chat.temporary.create`。Customer 不能创建临时会话。

到期清理或手动关闭后，会话保留历史但不再允许发送，当前版本没有重新打开入口。

## 顾客发起会话

顾客可以读取自己参与的会话。能否主动发起单聊由“顾客可发起单聊”团队设置控制；即使设置开启，目标仍需在当前团队 Chat 可用对象范围中。

顾客创建群聊还必须把“顾客群聊权限”设为“允许顾客创建”。顾客不能创建临时会话，也不能主动邀请其他 Customer。团队管理员的完整默认值和设置范围见[团队工作台](team-workspace.md)。

## 发送、编辑、撤回和已读

当前界面发送文本消息，单条最多 10000 字。发送 Entity 必须仍是会话有效参与者，且当前实体此刻仍有权代表它操作。

本人消息的编辑和撤回受团队时间窗口控制：

| 设置 | 默认值 | 0 的含义 |
| --- | ---: | --- |
| 消息编辑窗口 | 15 分钟 | 本人不能编辑 |
| 消息撤回窗口 | 2 分钟 | 本人不能撤回 |

编辑后显示“已编辑”；撤回后正文替换为“消息已撤回”。服务端的 `chat.message.moderate` 支持处理他人消息，但当前聊天界面只对本人消息显示编辑和撤回入口；该 Permission 也不会让无关 Entity 读取未参与的会话。

“显示已读回执”开启时，阅读消息会推进当前发送 Entity 的已读位置，参与者列表显示已读标记；关闭后系统不推进或展示该游标。

群聊历史由“新成员可见群历史”决定：

- **仅加入后消息**：新参与者只能看到加入之后的消息；
- **全部历史消息**：新参与者可以看到加入前的历史。

## 关闭会话

会话创建 Entity 的当前合法操作者，或具有 `chat.group.manage` 的当前实体，可以关闭会话。关闭是幂等操作：重复点击不会产生第二次关闭；关闭后只能查看历史，不能继续发送。

临时会话到期也会进入关闭状态。当前版本不提供重新开启、导出或复制整段会话的功能。

## 虚拟实体与 Webhook

虚拟实体是否可参与、可由谁操作，取决于 Team 中的实体状态和具体/通配 `chat.virtual.<slug>.act` Permission。当前操作者失去该 Permission 后，依赖该虚拟实体访问的会话会立即从可用范围消失。

Webhook 使用独立 API Token 代表所属虚拟实体发送消息，只能进入该虚拟实体已参与的会话。凭据不是共享登录密码，创建或轮换后明文只显示一次，管理方法见[团队工作台](team-workspace.md)。

## 消息保留

团队可以把消息保留天数设为 0–3650 天。0 表示永久保存；正数表示清理任务会删除超过期限的消息内容。保留策略作用于整个团队，不因单个参与者离开而停止，也不是用户自行删除历史的入口。

## 常见失败与恢复

| 现象 | 原因 | 恢复 |
| --- | --- | --- |
| 没有聊天团队 | 当前账号不是任何团队成员或顾客 | 加入团队或先在 Shop 绑定顾客 |
| 新会话候选为空 | 当前实体没有可联系对象，或对象无效/不可见 | 核对团队、对象状态和 Chat 设置 |
| 不能创建普通会话 | 缺少 `chat.conversation.create`，或顾客策略关闭 | 联系角色管理员或团队设置管理员 |
| 不能创建临时会话 | 缺少 `chat.temporary.create`，或发送 Entity 是 Customer | 改为普通会话或使用合适身份 |
| 不能代表虚拟实体发送 | 缺少目标 `chat.virtual.<slug>.act` Permission | 申请具体 slug 或通配权限 |
| 编辑/撤回失败 | 时间窗口已结束、消息已撤回或没有操作资格 | 保留消息状态，必要时联系消息审核者 |
| 会话突然不可见 | 当前身份、参与关系、虚拟实体或 `chat.virtual.<slug>.act` Permission 失效 | 回到 Account/Team 核对身份与授权 |

## 当前边界

- 登录账号本身不是聊天参与者，团队会话必须使用有效 Entity。
- 切换团队不会携带另一团队的会话、参与关系或 Permission。
- 当前界面以文本消息为主，不提供文件附件、反应、消息搜索、会话导出或重新开启关闭会话。
- Chat 不保存或修改实体资料；旧 `/profile` 按身份跳转到 Team 个人工作台或商城顾客中心。
- 页面当前不提供完整群参与者增删控件；服务端能力不等于界面已经交付。
- 详细身份、Permission 和错误恢复见[核心概念](concepts.md)、[权限目录](permissions.md)和[问题排查](troubleshooting.md)。
