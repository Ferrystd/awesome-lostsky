# 平台管理

Admin 管理 LostSky 平台本身，不代替团队管理员编辑成员、顾客、内容、订单或流水。普通团队运营者不需要进入本章。

## 功能基线

| 编号 | 用户目标 | 前置条件 | 应有结果 |
| --- | --- | --- | --- |
| ADMIN-01 | 查看平台概况 | `admin.dashboard.read` | 看到用户、团队、会话、管理员和近期关注项 |
| ADMIN-02 | 查询用户 | `admin.user.read`；敏感资料需额外 Permission | 查看脱敏资料、团队关系和有效设备 |
| ADMIN-03 | 治理用户 | 用户治理或会话撤销 Permission | 封禁、解封或撤销全部会话，并记录原因 |
| ADMIN-04 | 查询与治理团队 | `admin.team.read` / `admin.team.moderate` | 查看团队、域名和 Ability，并按权限封禁或解封 |
| ADMIN-05 | 管理平台管理员与角色 | `admin.access.read` / `admin.access.write` | 完整保存角色和管理员绑定，不破坏超级管理员安全线 |
| ADMIN-06 | 查看审计 | `admin.audit.read` | 按执行人、应用和资源查看脱敏事件 |
| ADMIN-07 | 查看系统状态 | `admin.system.read` | 看到核心依赖、积压和检查时间的只读状态 |
| ADMIN-08 | 管理 Ability 体验权益 | `admin.entitlement.read/write` | 配置平台权益包、公共体验活动与兑换码 |
| ADMIN-09 | 为团队开通能力 | `admin.team.ability.write` | 输入准确团队 slug，选择 Ability 与等级，设置永久或有限有效期并立即生效 |

完整平台 Permission 见[权限目录](permissions.md)。

## 进入 Admin

Admin 位于 `admin.lostsky.work`，不需要选择团队 Entity。所有页面先验证真实登录账号是否绑定有效平台角色：

- 未登录：前往 Account，成功后返回 Admin；
- 已登录但没有平台角色：显示明确的“没有访问权限”页面；
- 有平台角色但缺少某页 Permission：导航隐藏或禁用，直接访问也由服务端拒绝；
- `super_admin`：系统角色，拥有当前全部平台 Permission。

平台角色与团队角色完全隔离。团队 owner、团队角色管理员或 Team Entity 不会因此获得 Admin 权限。

## 平台总览

总览用于先判断平台状态，再进入具体治理对象。页面显示：

- 用户总数和近 7 日新增；
- 团队总数和近 7 日新增；
- 当前活跃设备会话；
- 平台管理员数量；
- 已封禁用户和团队；
- 最近用户、近期团队和最近审计事件。

总览是导航和风险提示，不代替详情核对。执行封禁或撤销会话前，应进入对象详情确认 ID、用户名/slug、团队关系和设备。

## 查询用户

用户列表可按用户名、昵称、手机号、邮箱或 ID 搜索，并按正常/已封禁筛选。联系方式默认脱敏：

| Permission | 可见与可搜索范围 |
| --- | --- |
| `admin.user.read` | 用户基本资料和脱敏手机号/邮箱 |
| `admin.user.sensitive.read` | 完整手机号/邮箱，并可使用完整值搜索 |

用户详情还显示平台角色、所属团队和有效设备会话。敏感 Permission 只扩大必要资料范围，不授予封禁或会话撤销能力。

## 封禁、解封和撤销用户会话

| 操作 | Permission | 结果 |
| --- | --- | --- |
| 封禁用户 | `admin.user.moderate` | 用户立即退出全部设备且不能重新登录 |
| 解封用户 | `admin.user.moderate` | 允许重新登录，但旧会话不会恢复 |
| 撤销全部会话 | `admin.user.session.revoke` | 全部设备和 Refresh Token 失效，用户需要重新登录 |

每次操作必须填写 5–500 字原因。原因、操作者、目标、请求标识和状态变化写入平台审计。

系统禁止管理员封禁自己。重复提交已经达到的状态不会重复改变对象或写入第二条相同治理事件。

## 查询与治理团队

团队列表可按名称、slug、所有者或 ID 搜索，并按正常、已封禁或已注销筛选。

团队详情显示：

- 团队名称、ID、slug、所有者和成员数量；
- 创建与更新时间；
- 标准/自定义域名绑定；
- 已授予 Ability 的键、等级和有效期。

具有 `admin.team.ability.write` 的平台管理员可从左侧“团队能力”输入准确的团队 slug，再从固定目录选择 Ability、合法等级和到期时间；该操作不需要 `admin.team.read`，页面不会展示或搜索全量团队。若管理员同时拥有团队读取权限，也可从团队详情点击“开通能力”自动预填 slug。提交会替换相同 Ability 的旧手工授权并立即重算团队有效能力；兑换活动产生的其他有效授权不会被撤销。永久授权把到期时间留空，有限期默认 30 天，也可选择未来的具体时间。不存在或已注销的团队不能开通能力。

该 Permission 不授予团队封禁、角色管理或平台体验权益管理能力；团队 owner 和团队角色管理员仍不能自行开通 Ability。每次直接授权都会记录执行管理员、团队、Ability、等级和到期时间，并进入平台审计。

封禁团队需要 `admin.team.moderate` 和 5–500 字原因。结果会立即让该团队全部标准域名和自定义域名不可用，但不删除团队内容，也不影响成员账号访问其他有效团队。解封后团队入口恢复，成员仍需使用有效登录和 Entity 会话。

已注销团队是终止状态，Admin 当前不提供恢复或继续封禁操作。

## 管理平台角色

平台角色把一组固定平台 Permission 分配给管理员账号。一个管理员绑定多个角色时，有效 Permission 取并集。

创建自定义角色时填写：

- 不可变的角色标识，例如 `support_operator`；
- 角色名称和说明；
- 完整 Permission 集合。

编辑时角色资料和 Permission 作为一个整体保存；失败不会只更新一部分。系统角色不可编辑或删除；仍被管理员使用的自定义角色也不能删除。

## 绑定平台管理员

在“平台管理员”中按现有用户 ID 添加管理员，并保存其完整平台角色集合。不能在后台修改自己的平台角色，以避免当前会话为自己扩大权限或意外锁死。

系统还会阻止任何导致平台没有可用超级管理员的操作。首位 `super_admin` 必须由有服务器权限的运维人员通过控制台授予；Admin 界面不能自举第一个超级管理员。

## 审计日志

审计页集中展示平台治理和已经接入集中审计的业务写操作，可以按执行用户 ID、应用和资源类型筛选，结果分页显示。每条记录包含动作、应用、资源、执行人、时间和已记录的非敏感原因/上下文。CLI 或系统事件可能没有 Entity 或认证用户，界面会显示为“CLI / 系统”。

当前不提供审计导出。审计页不会显示密码、Token、Cookie、Webhook 密钥或未登记的任意请求体。

## 系统状态

系统状态是只读检查，显示总体状态、检查时间、核心依赖和后台积压：

| 状态 | 含义 |
| --- | --- |
| 正常（`healthy`） | 核心检查通过 |
| 需关注（`degraded`） | 部分依赖或积压需要人工关注 |
| 异常（`unhealthy`） | 关键检查失败 |

页面会在进入、窗口重新获得焦点和短暂故障恢复后自动更新，没有队列重试、自动修复或手动“重新检查”按钮。发现异常时应记录检查项、消息和检查时间，再按运维流程处理。

## 安全线

- 不能修改自己的平台角色。
- 不能封禁自己。
- 不能删除系统角色或仍被使用的自定义角色。
- 不能执行导致没有可用超级管理员的操作。
- 前端入口只用于解释和减少误操作，所有治理写入由服务端再次鉴权。
- 完整手机号和邮箱必须有独立敏感信息 Permission，不能因拥有普通用户读取权限而自动获得。

## 常见失败与恢复

| 现象 | 原因 | 恢复 |
| --- | --- | --- |
| 提示没有访问权限 | 登录账号未绑定有效平台角色 | 联系 LostSky 运维绑定角色 |
| 页面或导航不可用 | 当前平台角色缺少对应 Permission | 核对页面所需 Permission，联系角色管理员调整 |
| 搜索不到用户或团队 | 搜索值不符，或缺少敏感资料 Permission | 核对用户名、ID 和筛选；需要完整手机号/邮箱时申请 `admin.user.sensitive.read` |
| 不能封禁、解封或撤销会话 | 缺少治理 Permission，或目标是当前管理员自己 | 使用具备 `admin.user.moderate` 或 `admin.user.session.revoke` 的角色，并核对对象 |
| 看不到“团队能力”或提交被拒绝 | 缺少 `admin.team.ability.write`，slug 不存在或团队已注销 | 核对准确 slug，并由平台角色管理员补齐独立 Permission；已注销团队不可恢复开通 |
| 不能保存角色或管理员绑定 | 缺少 `admin.access.write`，或操作会破坏超级管理员安全线 | 核对完整角色集合，并保留至少一个可用超级管理员 |
| 审计或系统状态不刷新 | 页面只读且按规则自动更新 | 重新进入页面或稍后查看；异常按运维流程处理 |

## 当前边界

- 不提供用户删除、密码重置、身份代办或团队内容编辑。
- 不提供 Ability 撤销、域名管理、商品/订单/流水治理或顾客余额调整。
- 不提供审计导出、队列重试、自动修复或在线控制台。
- 解封用户不会恢复旧会话；解封团队也不会绕过成员自身状态和 Entity 授权。
- 平台命令搜索可用 Ctrl/Cmd+K 或 `/` 打开；移动端使用导航抽屉。
- 无权限、对象状态和系统错误的恢复方式见[问题排查](troubleshooting.md)。
