# 公开主页与商城

团队商城默认不向客户开放。只有团队管理员开启“开放商城”，且 Shop Ability 当前有效时，已上架商品才会出现在商城首页、商品列表和 Display 实体页。关闭期间首页商品数按 0 处理、列表和实体商品区按空处理；直接访问旧商品链接或结账页会看到“商品暂未开放”。历史订单、客户资料、余额、卡密和已有服务权益仍可正常查看和使用。

Display 和 Shop 是团队对外前台。公开浏览不要求登录；维护商家客户资料、购买、查看订单和取消订单需要登录并领取该商家的 Customer Entity。

## 功能基线

| 编号 | 用户目标 | 前置条件 | 应有结果 |
| --- | --- | --- | --- |
| DISPLAY-01 | 浏览团队公开主页 | 团队有效 | 看到团队公开资料、实体入口和公开文档 |
| DISPLAY-02 | 浏览公开实体目录 | 至少一个有效且开启公开展示的成员或虚拟实体 | 按类型浏览公开 Entity |
| DISPLAY-03 | 查看公开实体 | Entity 有效且已公开 | 看到公开资料、公开角色、专属商品和公开文档 |
| DISPLAY-04 | 阅读公开文档 | 文档公开、同团队且归属公开有效 Entity | 未登录访客可安全阅读 Markdown 正文 |
| SHOP-01 | 浏览商品 | 团队有效且商品已上架 | 看到公开商品列表和脱敏详情 |
| SHOP-02 | 领取商家客户身份 | 已登录，当前来源尚未绑定该商家 | 创建或进入稳定 Customer Entity |
| SHOP-03 | 使用预存余额购买 | 当前商家 Customer 有效且余额足够 | 生成订单并按服务端金额扣减余额 |
| SHOP-04 | 维护当前商家资料 | 当前商家 Customer 有效 | 保存团队内昵称、头像、简介和服务归属 |
| SHOP-05 | 查看自己的订单 | 当前商家 Customer | 只看到当前 Customer 的订单和详情 |
| SHOP-06 | 取消自己的订单 | 订单属于当前 Customer 且处于“处理中” | 订单标记取消，预存余额只退回一次 |
| SHOP-07 | 保留邀请来源 | 从带合法 `ref` 的页面进入 | 同团队后续页面和分享链接继续携带来源 |
| SHOP-08 | 登记或修改客户归属 | 首次绑定或当前商家 Customer 有效 | 从同 Team 的 Team、成员或虚拟实体中选择，也可清空 |
| SHOP-09 | 管理商城商品与订单 | 当前 Entity 具有对应 Shop Permission | 在独立商城管理后台配置商品、服务权益与处理订单 |
| SHOP-10 | 查看我的业务订单 | 当前 Team、成员或虚拟 Entity，且有订单读取 Permission | 只看到自己作为接单人或发单人参与的订单 |
| SHOP-11 | 管理我的商品与权益资源 | 当前 Team、成员或虚拟 Entity，且有 `shop.product.self.manage` | 创建并管理自动归属当前 Entity、不可转移的服务、权益包、卡活动、卡密与商品 |

## Display 地址和公开范围

团队公开主页地址为：

```text
https://{team}.display.lostsky.work/
```

团队主页只要求团队本身有效，不由某个 Entity 的“公开 Display”开关控制。主页展示团队公开资料、公开实体入口和公开文档。

具备团队设置权限的管理员可以修改主页首屏欢迎语、实体入口、实体区域标题、说明和空状态提示。团队资料已经填写公开简介时，首屏优先显示该简介；“主页欢迎语”只在简介为空时作为回退。上述文案不会改变公开实体目录的标题、筛选和可见范围。

团队主页的实体区域是预览：桌面双列最多展示 6 个对象，即最多三行；移动端单列最多展示前 3 个对象。独立目录可直接访问 `/entities`，每页展示 20 个对象，并可按名称或 Slug 搜索、按“成员”或“虚拟实体”筛选；搜索词或类型变化时会回到第一页。本期导航和主页不提供独立目录入口，原有 `#entities` 锚点保持不变。

公开 Entity 必须同时满足：

- 属于当前团队且状态有效；
- 类型为成员或虚拟实体；
- 已开启公开 Display；
- 相关公开字段、角色、文档或商品还满足各自规则。

Customer 永不进入公开目录。Team 资料显示在团队主页，不作为成员/虚拟实体目录项。

“团队内可见”“全局可搜索”和“公开 Display”互不联动。一个成员可以在团队目录可见但不公开，也可以按管理设置公开但不参与全局 slug 搜索。

## 公开实体资料

实体详情展示公开资料、介绍媒体、Markdown、公开对象字段、公开角色、公开文档和专属商品。

- 公开字段只显示名称、类型、选项和值，不暴露管理范围、指定可见对象或搜索配置。
- 公开角色只显示名称和说明，不公开角色标识、Permission 或绑定记录。
- 客户引用和无效/隐藏 Entity 不会通过 Markdown 引用泄露内部资料。
- 介绍图片在实体页作为主视觉展示，不会在正文中重复一份。

专属商品只包括归属于当前 Entity 且已上架的商品。团队公用商品、归属其他 Entity 或已下架商品不会出现在该实体页。商品卡只公开名称、简介、封面和售价，不公开成本、分成或内部接单配置。

## 公开文档与分组

公开文档必须属于当前团队、可见范围为公开，且归属 Entity 有效并满足公开条件。私有、跨团队或归属隐藏 Entity 的文档不会因为知道文档编号而开放。

团队和实体页面可按资料中的“公开文档分组”组织文档：

- 分组按配置顺序显示，每项由标签和可选说明组成；
- 文档标签与分组标签必须完全一致，大小写不会合并；
- 空分组不显示；
- 同时命中多个分组的文档会在每个对应分组出现；
- 未命中任何已配置标签的公开文档继续显示在“公开文档”；
- 没有配置分组时，保持单一“公开文档”列表。

标签只参与 Display 分组，不改变文档搜索、排序、可见范围或 Permission。Doc Ability 失效会阻止团队后台管理文档，但已经公开的文档不会因此自动撤下。

## 邀请来源 `ref`

邀请链接格式为：

```text
https://{team}.display.lostsky.work/?ref=<邀请 Entity slug>
```

Team、成员和虚拟实体可以成为邀请来源，Customer 不可以。只要 URL 中出现当前团队合法 `ref`，浏览器会更新该团队的本地来源记录；之后浏览 Display、跳转同团队 Shop 或再次分享时，会自动补回该参数。

首次创建该商家的 Customer 时，服务端再次验证 ref：无效、跨团队、已失效或 Customer slug 会被忽略。合法来源成为客户初始归属。绑定完成后再打开其他邀请链接不会暗中改写已有归属；客户本人或授权后台管理员可以主动修改。

不要把 `ref` 当作折扣码、登录凭据或 Permission。它只记录客户来源/服务归属。

## 浏览商品

商城地址为：

```text
https://{team}.shop.lostsky.work/
```

访客可以浏览团队介绍、上架商品列表和商品详情。公开商品数据只包含名称、简介、Markdown 介绍、封面、售价和可选接单人，不包含成本、内部各方分配或管理字段。

商品已经下架、团队无效或链接编号错误时，详情不可购买。进入结账页后系统仍会在提交时重新核对上架状态和价格。

## 领取当前商家的客户身份

访问“我的资料”“我的订单”或结账时，Shop 会验证当前 Customer 是否属于该商家：

1. 未登录时先进入 Account，并在成功后返回原 Shop 页面。
2. 已登录但尚未绑定当前商家时，进入“领取客户身份”。
3. 确认后，为当前真实账号或来源 Entity 创建/读取该商家的稳定 Customer。
4. Shop 保存新的实体会话并返回原任务。

“领取客户身份”表单仅在当前链接带有有效邀请参数时只读显示邀请人，供提交前确认；页面不提供修改入口。未带邀请参数时不显示邀请人区域，表单与普通领取流程保持一致。这里仍沿用既有客户归属规则：只有当前商家同 Team 的有效 Team、成员或虚拟实体会成为初始归属，其他值会被忽略。

同一来源在同一商家只能绑定一个 Customer，绑定后不可转移到另一个账号或来源 Entity。不同商家拥有彼此隔离的客户资料、余额和订单。

来源 Entity 派生的客户会话会持续验证整条证明链。来源失效、父会话撤销、Customer 封禁或团队封禁后，旧会话不能继续使用。

## 商城客户中心

Shop 的 `/customer/profile` 是当前商家 Customer 的资料入口。Account 旧客户自管深链会安全跳转到这里。当前商家 Customer 可以维护：

- 当前商家内的昵称（必填）、头像和简介；头像既可粘贴已登记 URL，也可直接选择本地图片；
- 只读的全局客户 slug；
- 当前服务归属。

新绑定客户会自动得到 slug。只有历史上缺失 slug 的客户需要首次填写，领取后不可修改。客户昵称和简介只用于该商家的订单、会话和内部识别，不进入公开目录，也不产生公开客户主页。

服务归属候选只包括当前团队有效 Team、成员和虚拟实体，Customer 不能成为归属人。可以选择一个，也可以清空。修改只影响后续订单和流水的发单归属，不改写历史业绩。

保存时 Shop 只以当前 JWT 的叶子 Customer 为目标，不接受其他客户 ID。客户头像上传使用同一身份约束的 `/customer/upload`，受商家团队 File 等级容量和文件类型限制，未购买时使用 0 级 128 MiB，但不要求客户拥有后台 `file.upload` 角色权限；上传成功后自动回填 URL，仍需保存资料才会生效。团队后台具有 `team.customer.manage` 的 Entity 仍可以通过原管理接口修改客户资料、归属和封禁状态。封禁后 Shop 会显示明确状态，客户不能继续购买或访问受保护客户内容。

## 使用预存余额购买

选择商品后进入“确认购买”：

1. 选择 1–999 的数量。
2. 若商品只有一个接单人，系统自动采用；若有多个，必须选择其中一个；若没有配置，默认由 Team Entity 处理。
3. 可填写最多 1000 字给商家的备注。
4. 核对当前余额和应付总额，选择“使用余额购买”。

提交时服务端重新读取商品、接单人、数量和余额，并自行计算单价、总价、成本与各方分配。浏览器不能指定最终价格或内部金额。

余额不足时不能提交；当前版本没有在线充值，应联系商家由 Transaction 授权人员充值。订单、余额扣减和消费日志在同一事务中完成，失败不会只扣余额而没有订单。

订单保存商品名称、封面、单价和数量快照。商品后来改名或换图不会改写已经生成的订单记录。

## 订单状态与取消

| 状态 | 数值 | 客户可执行操作 |
| --- | ---: | --- |
| 处理中 | 1 | 查看详情；订单所属 Customer 可以取消 |
| 已完成 | 2 | 查看详情；不能再取消 |
| 已取消 | 3 | 查看详情和退款结果；重复取消不会重复退款 |

“我的订单”只返回当前 Customer 的订单。即使知道其他订单编号，也不能读取或取消。

取消处理中的订单会：

- 保留订单并标记“已取消”；
- 退回本订单使用的全部预存余额；
- 写入一条退款日志；
- 删除对应的自动关联流水（若曾生成）；
- 对重复请求不再第二次退款。

客户不能把订单标记完成；完成状态由商家业务流程处理。

## 商城管理后台

Team、成员与虚拟 Entity 都可访问 `https://{team}.shop.lostsky.work/manage` 的基础团队概览；团队和个人工作台都把“概览”固定为首个导航入口。商品、订单、服务、权益包与卡活动入口始终保留；缺少对应 Shop Permission 时入口显示为禁用，不在卡片内铺开权限错误，点击后由通用提示说明原因且不会进入业务页面。管理后台与深色商城前台使用不同界面：前台用于浏览与购买，管理后台用于连续完成商品、订单和履约配置。顶栏与 Team 工作台一致，桌面直接显示团队、商品、记账和聊天，移动端收进“操作”菜单，不显示应用下拉或个人/团队分段控件；团队概览以“进入个人工作台”进入个人概览，个人概览以“进入团队工作台”返回团队概览，再依次从“我的服务”“我的权益包”“我的卡活动”“我的商品”完成个人卡服务链路，或从“我的业务订单”查看当前 Entity 作为接单人或发单人参与的订单。跨应用切换会保留当前登录与 Entity 会话；向下滚动时顶栏随文档离开，不会遮挡商品或权益包表单。

“我的服务”“我的权益包”“我的卡活动”和“我的商品”统一要求 `shop.product.self.manage`，列表、详情和所有写操作都只作用于归属当前 Entity 的资源。新建资源自动归属当前 Entity 且不可转移；个人资源只能停用，不能硬删除。卡密继承卡活动归属，个人可以发行、查看、揭示和停用本人活动下的卡密。访问团队公用资源的管理详情或其他 Entity 资源会按不存在处理；保存前若已切换身份，页面会拒绝本次写入并要求重新进入当前身份的资源。

选择上游资源时，个人工作台只显示已启用的“本人”或“团队公用”候选，归属会直接标在候选名称后；其他 Entity 资源不会进入搜索。团队公用资源只能继续组合团队公用上游，本人资源可以组合本人或团队公用上游。停用资源不再进入新选择，但在本人管理列表和已有引用中仍保留名称与归属，便于识别历史配置。

团队商品与“我的商品”表单都可直接选择本地图片作为商品封面，也可在详情编辑器中上传图片；上传成功后系统自动回填已登记媒体 URL。直接上传使用团队当前 File 等级容量，未购买时为 0 级 128 MiB；商品保存继续按对应商品管理权限校验，不额外要求 `file.upload`。容量不足时本地上传入口会说明具体原因，但仍可粘贴已有媒体 URL，不影响其他商品字段的编辑与保存。

普通商品的售价在“销售与履约”中填写，成本与接单、发单、客服、团队分配集中在“默认分配”。修改售价或成本后，前三项按团队“服务履约”默认比例即时重算，团队分配自动显示剩余金额且不能直接修改；仍可手工调整前三项，保存前必须保证成本与全部分配不超过售价。服务套餐与卡密商品的金额继续由所选权益包自动汇总。

推荐配置顺序为：创建服务定义及接单池；把服务数量与有效天数组合成权益包；服务套餐商品直接绑定权益包，服务卡商品先创建卡活动再绑定；按需要配置核销字段并上架；最后在订单页处理手工订单、取消与完成。

编辑权益包时，每个服务项先显示服务、额度、有效期和单位价格摘要；展开后按“额度、价格与成本、分配”依次完成。选择服务后会自动填入该服务已设置的单位价格、成本与人员分配；如果在权益包中修改价格或成本，系统会像服务表单一样按团队默认比例重算接单、发单和客服的固定金额，团队分配自动取余额，不再选择分配方式。桌面与窄屏都使用相同的单列字段顺序，同组控件保持等宽，字段说明只在对应控件下方展开；上移、下移和删除集中在服务项头部，不会持续占用右侧空间或挤压输入框。

个人权益包中的本人服务始终可调整价格、成本和分配。团队公用服务默认沿用服务定义：新加入时以服务当前默认金额为基线，已有权益项保留创建时冻结的金额；没有 `shop.product.self.package.reprice` 时，这五项金额控件会显示禁用原因且服务端也会拒绝篡改，但额度和有效期仍可修改。拥有该独立权限后才可调整团队公用服务的商业金额。

卡密列表只显示脱敏片段。完整卡密仅在发行结果或用户主动点击“查看”时出现；停用卡密不会撤销已经领取的权益。

## Transaction Ability 缺失时

商城“自动同步记账流水”只有在团队设置开启且 Transaction Ability 等级至少为 1、未过期时生效。

Ability 缺失、过期或同步设置关闭时，购买和取消仍完整工作：订单创建、余额消费、余额日志和退款不受影响，只是不生成 Transaction 流水。因此 Transaction 报表中不会出现该订单，但这不代表客户支付失败。

## 常见失败与恢复

| 现象 | 原因 | 恢复 |
| --- | --- | --- |
| 公开实体或文档未显示 | Entity 未公开/无效，字段或文档非公开，或归属不满足 | 由团队资料管理员核对三套可见范围 |
| ref 没有成为归属 | ref 无效、跨团队、是 Customer，或客户早已绑定 | 核对邀请 slug；已绑定客户应主动修改归属 |
| 提示当前身份不属于商家 | 当前 Customer 来自其他团队 | 为当前商家建立独立客户身份 |
| 客户身份被封禁 | 商家后台已封禁 Customer | 联系商家核对状态；不能用重登绕过 |
| 余额不足 | 商家预存余额小于总价 | 联系商家充值或减少数量 |
| 必须选择接单人 | 商品配置了多个可选 Entity | 选择列表中的一个有效接单人 |
| 订单无法取消 | 订单不属于当前 Customer，或已完成/已取消 | 核对客户身份和订单状态 |
| 下单成功但没有流水 | Transaction Ability 或自动同步设置不可用 | 订单与余额仍有效；由团队检查联动条件 |

## 当前边界

- 首版没有购物车、优惠券、在线充值、第三方支付、提现或客户间转账。
- Display 首版只读，不提供加入申请、聊天动作、自定义域名、团队主题、SSR 或预渲染。
- Customer 绑定属于当前商家且不可转移；服务归属可以修改或清空。
- 客户资料按商家隔离，不作为公开账号资料。
- Shop 管理后台不提供购物车、在线支付、退款拆分或新的营销规则；这些能力不因管理界面上线而自动产生。
- Markdown 会安全过滤；图片延迟加载，视频需要访客主动播放。
- 登录、身份或订单失败的完整恢复见[问题排查](troubleshooting.md)。
