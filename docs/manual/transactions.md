# 记账与客户余额

Transaction 用于团队经营记录。所有金额、客户、参与 Entity、余额和绑定关系都以当前团队为边界。Transaction 不是银行账户或第三方支付工具；“余额”是商家在 LostSky 内维护的客户预存余额。

## 功能基线

| 编号 | 用户目标 | 典型前置条件 | 应有结果 |
| --- | --- | --- | --- |
| TRANS-01 | 查询流水 | Transaction Ability、`transaction.read` | 可筛选列表并查看当前团队流水详情 |
| TRANS-02 | 新建或编辑流水 | Transaction Ability、`transaction.write`，且满足记账主体范围 | 平衡金额、参与方和余额变动在同一操作中保存 |
| TRANS-03 | 删除手工流水 | Transaction Ability、`transaction.delete` | 流水删除，已消费预存余额安全退回 |
| TRANS-04 | 查看经营统计 | Transaction Ability、`transaction.report.read` | 按时间得到摘要、趋势、接单人、客户和归属业绩 |
| TRANS-05 | 维护发单绑定 | Transaction Ability；查看需 `transaction.read`，写入需 `transaction.write` | 客户与额外发单 Entity 的关系被保存或解除 |
| TRANS-06 | 查询客户余额 | Transaction Ability、`transaction.read` | 查看可用余额、累计充值/消费及完整变动日志 |
| TRANS-07 | 为客户充值 | Transaction Ability、`transaction.write` | 余额与充值日志在同一操作中更新 |
| TRANS-09 | 查看归属业绩 | Transaction Ability、`transaction.report.read` | 按流水创建时的归属快照统计客户数、流水数和金额 |
| TRANS-10 | 使用个人记账工作台 | 当前 Team、成员或虚拟 Entity，Transaction Ability 与对应 Permission | 流水、业绩、核销和绑定只按当前 Entity 的业务关系显示 |

Transaction Ability 缺失时“记账”应用入口仍可见但禁用。直接打开普通记账地址只读取访问快照并显示不可用说明，不请求流水、统计、核销列表、绑定或余额接口。唯一业务例外是收口已经开始的履约：具备 `service.redemption.manage` 的 Entity 仍可提交“确认已核销”，但不会生成或后补流水。其他 Ability 降级见[能力、权限与功能降级](access-and-abilities.md)。

个人工作台把“概览”固定为首个导航入口；相关流水、我的业绩、我的核销和客户协作保持为独立业务入口。个人工作台不提供 Entity 选择器，也不会把 Entity ID 发送给个人范围接口。服务端始终从当前 `acting_entity` 派生范围；即使拥有团队全量 Permission，个人模式也不会显示其他 Entity 的数据。

团队和个人工作台的基础概览不要求业务 Permission；两者都把“概览”固定为首个导航入口。个人概览以当前 Entity 名称为主标题，并同时说明类型与所属团队。流水、经营统计、服务核销、发单绑定、余额和登记动作的入口仍会显示；缺少所需 Permission 时入口禁用并给出原因。缺少 Transaction Ability 时仅保留不可用说明与应用切换；已开始履约的完成请求按上一段例外处理。

记账顶栏与 Team 工作台一致：桌面直接显示团队、商品、记账和聊天，移动端收进“操作”菜单，不显示应用下拉或个人/团队分段控件。团队概览以“进入个人工作台”进入个人概览；个人概览以“进入团队工作台”返回团队概览。向下滚动时顶栏随文档离开，不覆盖表单控件。两边概览只读取访问快照，不请求流水、统计、核销、绑定或余额数据。

## 流水类型

| 类型 | 数值 | 来源与操作边界 |
| --- | ---: | --- |
| 商城下单 | 1 | Shop 在联动条件满足时自动创建；不能在 Transaction 单独编辑或删除，应操作对应订单 |
| 记账登记 | 2 | 用户从“登记流水”创建；可按 Permission 和 Ability 编辑或删除 |

类型用于区分来源，不等于支付方式。现款和预存款在同一条流水中分别记录。

## 查看和筛选流水

流水列表按交易时间倒序显示，可以按关键词、时间、类型、接单人、发单人、客服和客户筛选。关键词主要匹配客户资料。

进入详情后可以查看参与 Entity、客户、总价、支付构成、成本与分配、交易时间和备注。`transaction.read` 同时允许读取流水表单的完整团队 Entity 和客户选项；选项出现不代表提交一定通过，服务端仍会检查对象状态和团队归属。

## 登记一条平衡流水

选择“登记流水”，按四组信息填写。

### 参与方

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 接单人 | 是 | 当前团队有效 Entity；创建后不可更换 |
| 发单人 | 否 | 当前团队有效 Entity；有客户当前归属时，系统优先写入该归属 |
| 客服 | 否 | 当前团队有效 Entity |
| 客户 | 使用预存款时必填 | 当前团队客户；用于余额消费、归属快照和客户统计 |

Team、成员、客户和虚拟实体可以作为业务参与 Entity，但具体候选和业务含义由团队流程决定。Customer 本身不能成为“邀请归属人”。

### 金额必须同时满足两条等式

```text
总价 = 现款 + 预存款
总价 = 成本 + 接单人分配 + 发单人分配 + 客服分配 + 团队分配
```

所有金额必须大于或等于 0，最多两位小数。表单显示“金额平衡”后才可保存。使用预存款时，客户可用余额必须不少于预存款金额。

### 记账主体范围

即使 Ability 和 `transaction.write` 均满足，当前 Entity 还必须符合以下任一情况：

- 当前身份就是 Team Entity；
- 当前客户归属于该 Entity；
- 当前 Entity 已通过“发单绑定”关联该客户；
- 新建的是没有客户的匿名/到店流水。

编辑既有流水不能依靠“匿名客户”规则绕过范围。无权维护该客户时，系统会拒绝保存。

### 保存结果

保存成功后进入流水详情。若使用预存款，流水与客户余额扣减、消费日志在同一数据库事务中完成；任一步失败都不会只保存其中一部分。

当选项接口暂时没有返回 `entities` 或 `customers` 时，表单仍会显示，但只禁用受影响的参与方、客户或预存款字段。不要把缺失选项当作空团队后强行提交。

## 编辑和删除流水

编辑记账登记流水时：

- 接单人不可更换；
- 客户、发单人、客服、金额、时间和备注可在允许范围内修改；
- 增加预存款会继续扣减客户余额，减少预存款会退款；
- 更换客户会先退回旧客户已使用预存款，再从新客户扣减；
- 客户有当前归属时，发单人优先使用该归属。

删除记账登记流水时，系统会退回该流水消费的预存余额并写入退款日志，再删除流水。商城订单流水不能单独编辑或删除，必须通过 Shop 订单取消/完成流程处理，避免订单、余额和流水失去一致性。

## 经营统计

统计页使用同一日期范围展示：

- 成交金额、流水笔数和平均单价；
- 现款、预存款和成本汇总；
- 每日成交趋势；
- 接单人分配排行；
- 客户贡献排行；
- 归属业绩中的成交客户、流水、成交额、成本和团队所得。

统计权限与普通流水读取分开。拥有 `transaction.read` 不代表能查看经营统计；统计还需要 Transaction Ability 和 `transaction.report.read`。

归属业绩按流水创建时写入的 `sender_entity_id` 快照统计。客户数是所选时间范围内发生交易的去重客户数；后来修改客户当前归属不会追溯改变历史报表。

经营统计页当前不提供生成或复制含邀请人参数链接的入口。已有链接中的合法 `ref` 仍按既有规则兼容处理，不会覆盖已经绑定的客户归属。

## 当前归属与发单绑定的区别

| 关系 | 数量 | 主要作用 |
| --- | --- | --- |
| 客户当前归属 | 每个客户最多一个，可为空 | 新订单或流水优先快照为发单人，并用于归属业绩 |
| 发单绑定 | 一个客户可绑定多个发单 Entity | 扩展哪些 Entity 可以在自己的客户范围内协作和记账 |

发单绑定不会替代客户当前归属。新增绑定时同一 Entity 与客户的重复组合会被拒绝；解除绑定不修改历史流水，也不清空客户当前归属。

查看绑定需要 Transaction Ability 和 `transaction.read`，新增和解除需要 Transaction Ability 和 `transaction.write`。Ability 缺失时绑定入口保留为禁用态，记账前端不会请求绑定接口。

## 客户余额与充值

“客户余额”展示：

- 当前可用余额；
- 累计充值；
- 累计消费；
- 按时间排列的余额变动明细。

余额日志类型为：

| 类型 | 数值 | 常见来源 |
| --- | ---: | --- |
| 充值 | 1 | Transaction 手工充值 |
| 消费 | 2 | 流水预存款支付或 Shop 下单 |
| 退款 | 3 | 删除/修改流水、取消订单 |
| 手动调整 | 4 | 历史或运维调整；当前界面没有单独调整入口 |

充值要求正数金额、Transaction Ability 和 `transaction.write`。成功时余额与日志同时更新；失败时不会只改动一边。商城客户不能在线充值，需联系商家由具备权限的 Entity 操作。

## 商城联动

Shop 的“自动同步记账流水”设置默认开启，但只有 Transaction Ability 等级至少为 1 且未过期时，新订单才生成类型为“商城下单”的关联流水。

联动不可用时：

- 订单仍会创建；
- 客户预存余额仍会扣减；
- 取消订单仍会退款且只退款一次；
- 订单和余额日志的关联流水 ID 为空；
- Transaction 统计不会出现这笔未同步订单。

这是一种明确的功能降级，不表示 Shop 下单失败。

## 常见失败与恢复

| 现象 | 原因 | 恢复 |
| --- | --- | --- |
| 记账整体显示不可用 | Transaction Ability 缺失、等级不足或过期 | 联系平台管理员恢复 Ability；期间不会读取流水、核销列表、绑定或余额，已开始履约仍可由有管理权限者完成但不记流水 |
| 只能查看，不能登记/编辑/删除 | 写/删 Permission 缺失 | 核对错误中的 Permission |
| 表单提示金额未平衡 | 两条金额等式至少一条不成立 | 重新核对支付和分配合计 |
| 预存款字段不可用 | 客户选项缺失，或尚未选择客户 | 等待选项恢复并选择客户 |
| 余额不足 | 客户余额小于预存款金额 | 先由授权 Entity 充值或改用现款 |
| 无权执行记账 | 当前 Entity 不是 Team、客户归属人或绑定发单人 | 调整归属/绑定，或切换合法身份 |
| 商城流水无法编辑/删除 | 它由订单联动生成 | 回到订单流程操作 |
| 报表空但存在订单 | 时间范围不匹配，或订单未同步为流水 | 核对日期和商城联动条件 |

## 当前边界

- 当前身份必须属于地址对应团队，不能凭其他团队角色直接读取数据。
- 页面允许选择的对象不代表最终授权，提交时仍重新校验 Entity、客户、余额、Permission 和团队归属。
- Transaction 只记录团队经营数据，不执行银行卡充值、收单、提现或第三方支付。
- 列表数据会在进入、窗口重新聚焦和操作后更新；写入结果不确定时先核对详情，避免重复提交。
- 完整访问错误见[问题排查](troubleshooting.md)。
