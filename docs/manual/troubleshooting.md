# 问题排查

遇到入口禁用、跳转、403、未找到或保存失败时，按“账号 → 当前身份 → 团队 → Ability → Permission → 内容与业务状态”的顺序排查，通常能快速定位责任人。

## 常见提示与恢复方法

| 现象或提示 | 含义 | 恢复方法 |
| --- | --- | --- |
| 跳转到 Account 登录 | 未登录、登录过期、设备会话被撤销或用户被封禁 | 重新登录；若仍失败，确认账号状态 |
| 要求领取成员身份（`42801`） | 已登录，但没有当前实体(Entity) | 在回调页领取地址对应团队的本人成员；没有成员关系时先申请加入或联系管理员 |
| 当前身份属于其他团队（`40301`） | Entity 与地址中的团队不一致 | 核对目标团队后确认切换；取消会保留原身份 |
| `缺少权限(Permission)`（`40302`） | 当前实体的角色不包含所需键 | 把完整 Permission 键发给团队角色管理员 |
| `当前团队缺失能力(Ability)`（`40303`） | 团队未开通、等级不足或能力过期 | 把 Ability 键和团队 slug 发给 LostSky 平台管理员 |
| “未找到”或 404 | 链接错误、对象无效/跨团队，或对象对当前身份隐藏 | 核对团队、slug/编号和对象状态；由有全量读取权限的管理员确认 |
| 余额不足 | 顾客预存余额小于本次支付 | 联系商家通过 Transaction 充值；当前版本不能在线充值 |
| “该团队文件已达到上限，请联系团队管理员。” | 当前 File 等级的团队总容量已用尽；未购买时为 0 级 128 MiB，文件数量不受限制 | 由具备 `file.delete` 的管理员删除不再需要的文件，或由具备 `team.ability.redeem` 的管理员进入“团队能力”升级 File 等级 |
| 上传后提示“服务响应格式异常”，但文件库已有记录 | 服务端响应被 PHP 告警或其他非 JSON 内容污染，前端无法安全读取返回的文件 URL | 联系运维检查 PHP `upload_tmp_dir` 是否存在且可写，并确认生产环境关闭 `display_errors`；修复后重新上传或从文件库复制已有文件 URL |
| 操作不允许或 422 | 输入、资源状态或业务前置条件不满足 | 根据字段提示修正；订单、申请、会话等只能在允许状态执行对应动作 |

## 登录后没有团队

“我的团队”只列出当前账号已经创建或加入的团队。

- 需要个人工作空间：选择“新建团队”。
- 已向团队提交申请：等待审批通过，刷新后团队才会出现。
- 管理员声称已添加：请管理员核对添加时使用的 user ID 和成员状态。
- 账号登录错了：退出后使用原手机号、用户名或邮箱登录。

LostSky 不会自动为每个账号创建个人空间。

## 团队存在，但没有可领取身份

基础账号只能直接领取与本人关联的有效成员或顾客实体。候选为空时检查：

1. 成员或顾客是否已关联当前真实账号；
2. 对象是否有效且未封禁；
3. 对象是否已有全局 slug；历史缺失对象需要先完成首次领取；
4. 若想领取团队、虚拟实体或其他人的实体，当前实体是否获得相应 `identity.*.assume` Permission。

旧身份被撤销、对象封禁或委托 Permission 被收回后，依赖它的会话会在下一次请求失效，需要回到 Account 选择仍有效的身份。

## 有权限，入口仍然不可用

先区分 Ability 和 Permission：

- Permission 属于实体的角色，团队角色管理员可以调整；
- Ability 属于团队，由 LostSky 平台运维开通或续期；
- Doc、File、Transaction 的具体降级见[能力、权限与功能降级](access-and-abilities.md)。

还要确认角色是分配给「当前正在使用的实体」，而不是只分配给登录账号的另一个成员或顾客实体。切换身份后权限会重新计算。

## 页面是空的，但管理员说有数据

空列表不一定表示团队没有数据，也可能表示当前身份只能看到基础范围：

- 实体目录隐藏 Customer 和团队内隐藏对象；
- 成员目录隐藏团队内不可见或封禁成员；
- 顾客目录在没有全量读取权限时只显示归属于当前实体的顾客；
- 文档按可见范围过滤；
- Display 只显示有效、公开且非 Customer 的实体和公开文档；
- 搜索条件、状态筛选和时间范围也会产生“无匹配结果”。

先清空搜索和筛选，再由具备对应全量读取 Permission 的管理员核对。对于隐藏对象，系统可能统一返回 404，以避免泄露其存在。

## 保存后结果与预期不同

- 角色、Permission 和实体角色分配都按“完整集合”保存；取消勾选会移除旧项。
- 顾客当前归属改变后，只影响后续订单和流水，不追溯历史归属业绩。
- 文档标签大小写敏感；展示分组只匹配完全相同的标签文字。
- 公开角色只控制名称和说明展示，不会改变授权。
- 团队内可见、全局可搜索和公开 Display 相互独立。
- 商城自动记账还要求设置开启且 Transaction Ability 有效；不生成流水不代表订单或余额失败。

## 网络中断或页面没有更新

避免连续重复提交写操作。先确认页面是否已经出现成功提示或新记录，再重新进入该页面。Team 和 Admin 的主要数据会在重新进入、窗口重新获得焦点和操作完成后自动更新；部分前台错误页提供“重试”。

若登录过期，系统会回到 Account，并在安全范围内保留原任务地址。重新登录后仍应核对当前团队和身份，不要依赖浏览器后退继续使用旧表单。

## 向管理员反馈什么

请提供：

- 当前页面地址（可以隐藏无关查询参数）；
- 团队名称与团队 slug；
- 当前实体类型、名称和 slug；
- 操作时间和准备执行的动作；
- 完整错误文案、Permission 或 Ability 键；
- 可复现步骤和必要截图。

不要发送密码、短信验证码、Access Token、Refresh Token、Webhook Token、签名密钥、Cookie 或包含这些内容的完整网络请求。
