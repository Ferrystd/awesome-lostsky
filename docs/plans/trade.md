# 卡密、订阅与资产交易计划

> 状态：部分能力已由现有应用覆盖，统一资产与支付流程仍待设计。本页只记录剩余设想，不代表已确定的路由或接口。

## 已有能力与归属

不要重新建设已有链路：

- [Shop](../apps/shop.md) 已提供商品与服务包购买、订单、卡活动、卡密发行、顾客持有卡密及服务权益；当前购买使用商家预存款，不提供在线充值或第三方支付。
- [Admin](../apps/admin.md) 管理平台 Ability 权益包、公共体验活动与兑换码；平台权益和团队商家权益相互隔离。
- [Team](../apps/team.md) 提供团队 Ability 兑换入口；[Transaction](../apps/transaction.md) 提供独立服务权益下发与核销，不为手工下发创建商城订单。

## 剩余设想

- 统一资产入口：是否跨团队汇总订阅、剩余时间与配额、持有卡密，需要先定义资产归属、跨团队读取权限和脱敏范围。
- 按面额购买卡密、仅验证而不消费卡密：需要另行确认产品模型与防枚举、核验限流规则，不能直接复用揭示卡密明文的接口作为公开校验接口。
- 继续支付未完成订单：依赖独立支付单、回调与退款状态机；当前预存款购买流程不具有这套在线支付语义。支付前置要求见[待办中的 Shop 在线支付](../TODO.md)。

## 实施与验收前置条件

确认用户目标、资产与支付模型后，再定义应用归属、Permission、数据生命周期和 OpenAPI。验收至少覆盖归属隔离、重复提交、过期与撤销、支付回调重放、失败补偿及余额一致性；未完成这些设计前，不把剩余设想写成现行功能。
