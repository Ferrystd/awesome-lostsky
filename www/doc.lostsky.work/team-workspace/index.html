团队工作台¶

工作空间内入口提供基础阅读，不把“读取全部数据”的权限当作页面门票。管理内入口保持稳定：有相应读取权限时可进入只读页，完全无权时显示禁用态。禁用原因通过控件说明和短时全局提示提供，不在侧栏或内容区常驻报错。界面状态不替代服务端鉴权。

功能基线¶

编号 用户目标 典型前置条件 应有结果
TEAM-01 维护自己的团队资料 当前团队成员身份 可查看并保存本人允许编辑的资料
TEAM-02 管理实体与扩展字段 对应实体或字段权限 字段定义、资料值和公开设置按权限生效
TEAM-03 管理角色和权限 角色读写权限 角色、权限集合及实体角色分配被保存
TEAM-04 管理文件和文档 对应内容权限；文档能力已开通 内容保存到当前团队并按可见性提供
TEAM-05 阅读或发送通知 Team 共享站内通知需要查看权限；发送需要发送权限 通知进入正确收件箱，并按收件 Team 或实体共享已读状态
TEAM-06 申请加入团队 已登录且不是当前团队成员 申请可提交、查询和在允许阶段取消
TEAM-07 审核加入申请 加入审核权限 申请进入审核流程，并被同意或拒绝
TEAM-08 配置虚拟实体与 Webhook 对应管理权限 Chat 可使用已保存且有效的配置
TEAM-09 从工作台进入对话 当前身份可使用所选团队的 Chat 进入团队消息页，或在实体与成员上下文中预选聊天对象
TEAM-10 查看和管理团队客户 当前实体为客户归属人，或具有客户读取/管理权限 查看权限范围内客户；管理者可修改资料、归属与封禁状态

个人资料与实体¶

“我的资料”用于维护当前成员自己的昵称、简介和被允许编辑的扩展字段。字段是否出现由可见范围决定；本人只有在字段允许本人维护且未锁定时才能修改。隐藏、只读、其他对象类型的字段不会因为页面提交而变得可编辑。

“实体”统一浏览团队、成员、客户和虚拟实体等可被授权或引用的主体；只处理成员特有任务时才进入“成员”。实体和成员分别有独立的“团队内可见”状态：Team 与成员默认可见，公开展示的既有虚拟实体迁移为可见，其他虚拟实体和 Customer 默认隐藏。

  • 没有 team.entity.read 时，仍可进入实体目录并查看有效、非 Customer 且团队内可见的实体；具有该权限时可读取全部有效实体，包括 Customer 和团队内隐藏实体。
  • 没有 team.member.read 时，仍可查看有效且团队内可见的成员；具有该权限时可读取包括隐藏或封禁成员在内的完整管理集合。
  • 无权访问团队内隐藏实体或成员时，直接链接返回“未找到”，不泄露其是否存在。
  • team.entity.profile.manage 控制实体资料、团队内可见状态和公开主页状态。缺少该权限时同一详情页以只读方式打开，入口文案显示“查看”。

“团队内可见”“全局可搜索”“公开 Display”是三套互相独立的展示范围：团队内可见只服务当前工作空间目录；全局可搜索决定跨页面实体搜索；公开 Display 决定互联网访客可见内容。开启其中一项不会自动开启其他项。

成员列表支持按昵称、Slug 或用户 ID 搜索，并按全部、正常、已封禁和未领取分类。实体或角色分配中的对象搜索统一使用带类型、名称、Slug 和全局标识的候选结果，不要求操作者先记住并完整输入 Slug。

工作台的抽屉、搜索候选、加载/空状态和筛选后的列表变化使用短时过渡帮助确认空间与状态关系，不会在进入页面时逐项播放。系统开启“减少动态效果”后，这些过渡会近乎即时完成，功能与信息保持不变。

工作台顶栏和概览提供团队消息入口；实体、成员列表及详情中的“对话”入口会进入当前团队的 Chat 新会话页，并预选该对象。预选不绕过 Chat 的身份、对象可见性或会话类型限制；目标当前不可联系时，Chat 仍以自己的可用对象范围为准。

“客户”入口用于团队客户关系管理。当前归属实体即使没有全量读取权限，也能查看归属于自己的客户和详情；team.customer.read 可查看全部客户，team.customer.manage 可修改客户团队内资料、服务归属和封禁状态。归属只能选择当前团队有效的 Team、成员或虚拟实体，也可以清空。客户详情提供订单与流水摘要，并可在 Chat 能力和权限允许时发起对话；页面不会暴露用户手机号、邮箱或底层 user ID。

对象字段的“可见范围”只过滤已经有权打开的资料，不会额外授予页面或接口权限；“团队管理可见”仅向拥有对应字段管理权限的实体提供，“主体本人和团队管理可见”额外允许字段所属对象查看，“团队人员可见”允许当前团队内的有效实体查看，“公开可见”还要求所属实体有效且已开启公开主页展示，“指定对象可见”只额外允许选定实体查看。可见不等于可编辑。

字段的“值维护范围”决定对象本人是否可以参与维护；“允许修改字段值”关闭后，字段管理员和对象本人都只能查看。当前版本仅在人员“我的资料”中提供本人维护入口。字段值搜索尚未开放，“允许搜索”配置保留为后续能力，不参与当前可见性判断。

角色与权限¶

角色把一组权限分配给实体。一个实体拥有多个角色时，有效权限取各角色权限的并集。

建议先创建职责清楚的角色，再编辑完整权限集合，最后在“实体角色分配”中选择承担该职责的实体。角色的“公开展示”只决定名称和说明是否出现在公开资料，不会增加或减少授权。

删除角色会使相应绑定失效。修改权限前应确认是否会让现有负责人失去进入页面、处理申请或恢复配置的能力。

文件、文档与通知¶

文件保存在当前团队空间。文档可以归属于团队内有效实体，并设置管理范围、可见性和指定可见对象；只有公开文档才会出现在 Display。文档列表支持按标题或 Markdown 正文搜索，并按可见范围分类。

缺少 File Ability 时，文件页上传按钮和 Markdown 编辑器原有的图片上传图标保持可见但不可操作，并提供 当前团队缺失能力(Ability): 文件上传(File)；不会额外增加第二个“上传本地图片”按钮，文档编辑和外部图片 URL 仍可正常使用。缺少上传 Permission 时提供 缺少权限(Permission): file.upload。上传按钮预检查通过后若权限或能力被撤销，页面仍会展示服务端返回的同一具体原因，不会静默失败。

缺少 Document Ability 时，文档导航以禁用态展示，直接打开文档列表、创建、编辑或详情地址会返回工作台概览并给出短时原因提示；File Ability 不控制文档入口或文档处理能力。

通知分为两种单向通道：

  • “站内通知”是 LostSky 发给 Team 的共享通知，需要 team.notice.read，因此入口位于“管理”。
  • “通知”是有 team.notice.send 权限的当前实体代表 Team 发给同 Team 实体的通知；查看当前实体收件箱不需要额外权限，因此入口位于“工作空间”，发送入口位于“管理”。

拥有发送权限即具备本通知模型中的上级资格，不再按角色排序建立第二套层级。通知可发送给 Team、成员、客户或虚拟实体，统一显示 Team 为发送方，实际操作实体和认证用户保留在业务审计中。每条通知的已读状态由其收件 Team 或实体共享。

通知不支持回复、抄送、会话或跨 Team 投递；本期也不提供 LostSky 直接向实体发送通知的入口。

加入与审核¶

访客在团队加入页读取申请表单、填写资料和备注后提交申请。申请人可以查看自己的记录，并在允许取消的阶段撤回。

审核人员可配置申请字段、查看申请、维护审核任务并同意或拒绝。被配置为“通过后转存”的申请字段，会在申请获批并创建成员时写入对应实体字段。

当前边界¶

  • 所有管理操作仍由服务端校验权限；界面隐藏按钮不是授权机制。
  • 概览固定显示实体、成员、文档和通知。拥有对应的实体、成员或文档全量读取权限时显示具体数字；否则显示进入箭头。单项接口失败只影响对应卡片，不会把失败伪装为 0。
  • 没有 team.entity.read 时，实体目录只显示团队内可见的非 Customer 实体；Customer 和团队内隐藏实体不会出现在列表中，直接访问也返回不存在。
  • 禁用操作通过 title、无障碍说明和点击后的短时全局提示提供原因；提示会自动消失，不在侧栏或页面两侧常驻。Permission 与 Ability 使用原始键，便于向团队负责人申请权限或能力。
  • 缺少当前身份时应进入身份选择；身份属于其他团队时应明确提示确认切换。
  • 私有内容、无权查看的内容和无效实体不会因为知道链接而变得可访问。
  • Webhook 是团队集成能力，不应用作共享用户登录凭据。
