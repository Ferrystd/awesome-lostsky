Changelog¶

注意：v0.1.4 的变更日志由 GitHub Copilot（DeepSeek V4 Pro）辅助编写，人工审核并确认。

未发布（目标 v0.1.5）¶

新增¶

  • Account 新增“当前实体中心”，统一支持成员、虚拟实体和客户维护有限资料、本人对象字段，并只读查看角色与有效权限。
  • Shop 新增商家后台，统一管理商品、订单、服务权益、三类卡密及核销交付流程。
  • Transaction 支持服务收款与核销流水，并提供分阶段核销自定义字段。
  • Team 与 Admin 新增 Ability 权益、体验活动以及卡密预检和兑换管理。
  • Display 支持配置主页文案，并新增可搜索、筛选和分页的公开实体目录。

变更¶

  • Team“我的资料”、Shop 客户资料和 Chat 资料入口统一迁移到 Account；所有当前实体写入使用 expected_entity_id 阻断身份切换后的旧表单。
  • 成员入离职流程支持申请字段、邀请来源、资料转存、自助离队、管理员办理离职及原身份复职。
  • 公开文档支持自定义标签，并可在团队和实体主页分组展示。
  • 后台统一表单、列表、状态反馈和响应式交互，实体选择器可区分同名对象。
  • 经营统计停止提供客户邀请链接，客户空状态不再依赖该入口。
  • 发布交付改用不可变标签，并可由标签和提交共同定位。
  • 团队角色支持授予父级 Permission，自动覆盖其下的业务权限。

修复¶

  • 修复 Team 禁用入口错位、客户详情路由误匹配及异常数据导致整页空白的问题。
  • 权限不足或选项缺失时保留可用操作，并统一给出可配置的权限与能力提示。
  • 修复登录、侧栏、文档编辑器及后台控件的样式退化。

v0.1.4¶

新增¶

  • 展示页与商城新增邀请 ref 持久传播：首次建立客户身份时登记同团队邀请实体，客户二次转发和跨页面访问不丢失来源。
  • 团队工作台新增客户列表与详情，支持归属范围读取、资料/归属/封禁管理和 Chat 对话入口；新增 team.customer.read、team.customer.manage。
  • 商城顾客中心允许客户本人查看、修改或清空服务归属；流水统计新增归属业绩和当前实体邀请链接。
  • 收紧团队实体基础目录：Customer 始终要求 team.entity.read，既有未公开虚拟实体默认转为团队内隐藏；新增 team.document.read 控制文档全量读取与概览计数，无权限时文档卡显示进入箭头。
  • 修复团队文档阅读页未兼容分页列表详情响应而显示“未命名文档”和空正文的问题，并重整阅读层级、元信息与加载/错误/空正文状态。
  • 实体与成员新增独立的团队内可见状态；team.entity.read 与 team.member.read 调整为全量读取权限，基础目录继续向所有团队 Entity 提供内部可见内容。
  • 团队新增通用访问快照和访问感知概览接口，概览固定展示实体、成员、文档和通知，并支持单指标降级。
  • 团队工作台新增“查看公开主页”，实体详情新增团队内可见控制和已公开实体直达入口。
  • 团队工作台在顶栏、概览、实体与成员列表及详情中新增上下文对话入口，可直接进入当前团队消息页并预选聊天对象。
  • 新增独立的 Admin 平台治理应用，覆盖平台 RBAC、用户与团队封禁、会话撤销、集中审计、系统状态、CLI 超级管理员自举，以及桌面和移动端管理界面。
  • 新增 team.notice.read 与通知能力接口，分别控制 Team 共享站内通知入口并向前端返回站内通知查看、通知发送和默认收件箱能力。
  • 新增 certificate:update 命令，以一张多 SAN Let’s Encrypt 证书统一更新全部 Nginx 前端/API 域名和 OSS 自定义域名，并支持 Certbot 续期钩子。
  • 新增 team:grant-ability 命令，支持通过服务器终端为指定团队幂等授予、更新或恢复 Ability。
  • 公开实体详情新增该实体已上架专属商品陈列，并可直接进入同团队商城查看和购买。

变更¶

  • 新增独立的 doc.lostsky.work 用户指南站，与完整的 docs.lostsky.work 文档站复用 docs/manual/ 正文，并按用户任务提供精简导航；补充双站 Linux 与 Windows 宝塔/Nginx 部署基线。
  • 客户资料管理从 Chat 迁入 Shop 顾客中心：资料按商家团队隔离且不公开，Shop 提供读取、更新与历史 slug 首次领取接口；Chat 旧 /profile 只按当前 JWT 身份跳转到 Shop、Team 或 Account。
  • 团队成员、文档与文件列表统一为克制的搜索筛选工具栏和连续列表；成员增加状态分类，文档增加可见范围分类与标题/正文搜索。
  • 实体角色分配改用带名称、类型、Slug 和全局标识的候选搜索；Admin、Team 与 Transaction 的普通搜索框统一视觉与清除行为。
  • 短时操作反馈收口到全局提示函数，自动消失并抑制重复消息；禁用导航不再在侧栏或页面两侧常驻权限提示。
  • 缺少 Document Ability 时封闭文档导航和直接路由；缺少 File Ability 时只禁用文件上传与 Markdown 原图片上传图标，不新增替代按钮，也不影响文档处理。
  • 管理导航保持结构稳定：无权限入口以可聚焦、可点击的禁用态展示具体 Permission；实体和成员详情在只有读取资格时进入只读模式。
  • 文件页、资料上传和 Markdown 图片上传统一区分 File Ability 与 file.upload Permission，保留外部 URL，并显示服务端撤权后的具体错误。
  • 对象字段统一使用可见范围、值维护范围和可编辑状态控制读取与修改，字段管理页支持公开及指定对象可见，并移除旧“人员本人可见”字段。
  • 对象字段“允许搜索”在字段值搜索能力完成前退出管理表单，后续启用条件转入待办事项。
  • 对象字段表单统一访问规则与布尔设置的表面、圆角和留白，移除嵌套卡片造成的视觉层级冲突。
  • 团队工作台侧边栏采用深色细滚动条，并在下方仍有入口时显示可点击的发光下箭头提示。
  • 后台统一动效令牌与缓动，抽屉、遮罩、候选菜单、异步状态和筛选列表使用克制的状态过渡；首次页面渲染不做编排，并完整支持系统“减少动态效果”设置。
  • 删除trade应用的计划
  • 实体引用胶囊和展开卡片按团队、成员、客户、虚拟实体显示可区分的语义色，未知或不可用对象保持中性灰。
  • 团队工作台侧边栏新增成员管理入口，实体与成员专属任务保持相邻。
  • 统一团队工作台通知术语：“实体通知”改为“通知”，“发送实体通知”改为“发送通知”，“站内信”改为“站内通知”。
  • 团队通知正文支持可视化 Markdown 编辑、源码与预览模式，阅读页统一进行安全 Markdown 渲染。
  • 发送通知的候选实体改为带类型图标、类型标签与独立全局标识的分层选择列表。
  • 团队通知拆分为工作空间中的“通知”、管理中的“站内通知”和“发送通知”；通知接口以 scope=team|entity 区分收件箱，允许 Team 实体接收通知，并保留旧路径与省略 scope 的兼容行为。
  • 根开发提示词要求任务开始前读取 Wiki 索引及相关规则，前端改动完成后执行完整静态发布构建。

修复¶

  • 修复本地 Vite 代理误用生产 HTTPS 地址时，证书或静态站点兜底响应被浏览器表现为 CORS 的问题，并扩充 CORS 静态检查。
  • 修复文件空状态图标偏到内容区左侧、文档列表乱码与检索能力不足，以及 Markdown 编辑器重复出现本地上传按钮、禁用图片按钮仍会插入待上传节点或在刷新后干扰正文焦点且不提示原因的问题。
  • 修复 PHP 上传临时目录异常污染 JSON 时前端无反馈的问题：部署基线要求可写临时目录并关闭生产错误直出，上传界面同时增加可见错误区域。
  • 移除概览通用权限红色横幅和失败后伪造的零计数，单项失败不再影响其他卡片。
  • 修复对象字段可见范围仅在公开展示中部分生效、成员关联读取可能返回隐藏字段，以及“允许编辑”与本人编辑权限混淆的问题。
  • 修复 Admin 联系方式搜索绕过敏感权限、团队封禁缓存延迟、RBAC API 审计误记为 CLI、角色资料与权限部分保存，以及 OSS 故障阻断 Nginx 证书重载的问题。
  • 修复 Admin 用户与团队搜索在真实 MySQL 查询中无法解析关联表字段的问题，并使 Admin 集成 fixture 可在已有超级管理员测试数据的数据库中重复运行。
  • 公开文档中的实体引用卡片改为撑满文档内容区，同时保留正文阅读行宽。
  • 团队概览入口改为“使用文档”，未读消息只统计未读项，并为既有团队 owner 角色补齐实体目录与资料管理权限。- 修复团队文档中 Markdown 实体引用解析（/entity/resolve）错误使用 is_searchable（全局搜索可见性）判断可用性，导致团队内可见但不可搜索的成员引用显示为"对象不可用"；现改为同团队实体仅检查 is_valid，跨团队实体仍保留 is_searchable 控制。

v0.1.3 (2026-07-29)¶

新增¶

  • Account 新增短信验证码注册与登录，支持在阿里云短信服务和号码认证服务的短信认证之间切换；开发环境可通过双重开关安全跳过短信。

变更¶

  • Account 注册时强制设置密码，密码登录统一支持手机号、用户名和邮箱；新密码使用安全哈希保存，历史明文密码在首次成功登录后自动迁移。
  • 短信通道类型改用 SmsType 枚举并统一由 config/auth.php 选择；短信策略、签名和模板退出 .env，环境变量仅保留阿里云 AccessKey 等关键部署参数。
  • 后端请求参数统一按路径、查询和请求体分别使用 route()、get()、post()，基础类型在 Request 边界通过后缀转换；Shop、Transaction 的路径 ID 改用应用级全局整数规则。

v0.1.2 (2026-07-26)¶

新增¶

  • 新增团队公开主页与展示型商城，覆盖公开实体、角色、文档、商品详情、客户身份、余额结账、订单历史及移动端体验。
  • 通知支持 Team → Entity 投递，并为成员、客户和虚拟实体提供独立收件箱与已读状态。
