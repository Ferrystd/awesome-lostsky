后台应用与页面规则¶

本页登记应用专属边界和页面例外；未登记的行为必须服从公共规范。

Team¶

  • Team 侧栏底部“退出登录”必须保持 44px 以上触控高度，并与同栏导航图标、文字左对齐；桌面固定侧栏与移动抽屉使用同一结构，键盘焦点和退出行为沿用 NButton，不得因组件库默认居中样式改变位置。加载、空、错误、权限和 Ability 均不影响该全局会话操作；无例外。验收时以源码契约检查 .logout 的左对齐，并在 TeamShell 组件预览及桌面、移动端 E2E 中确认位置和可操作性。
  • 实体、成员、客户及所有候选项统一使用 LsEntityIdentity；媒体为圆角方形，真实头像优先。此前实体与成员分别使用圆形和方形不是巧思，而是没有语义依据、会破坏主体识别的一致性问题，不得恢复。
  • 实体、成员、客户、文件、文档、角色、虚拟实体、申请字段、通知、加入审核是集合页，必须有 LsListToolbar。
  • 成员移动端以“管理/查看”为主操作，对话、预览、封禁、离职进入更多；危险操作不得成为主操作。
  • 客户列表不得再嵌套第二个 LsPage；通知和审核使用连续列表。
  • 实体、成员、客户、文件、文档、角色、虚拟实体、对象字段、申请字段、通知、加入审核、资源页和团队设置的页面级无数据统一使用 LsEmptyState；创建入口仍位于页面标题，不进入空状态组件。
  • 上传缺少 Ability 时只禁用文件选择，不显示常驻错误。加入申请的动态文件字段统一使用 LsUploadField，其余动态字段使用对应 Naive UI 控件；缺失必填项时阻止提交并在字段区域说明，不得让协议字段回退到页面级原生控件。
  • 加入申请页仅在链接包含有效邀请参数时，以非输入控件只读确认当前邀请人，不允许申请人改写链接带入的来源；没有邀请参数时不得渲染邀请人区域，页面结构与引入该功能前保持一致。成员详情将加入时间与邀请人放在独立的成员信息区，邀请人必须按全局 Entity 展示并明确标注其他团队来源。
  • Team 成员管理仍可复用 MemberProfileFields 和 useMemberProfileUpload；实体本人编辑已迁入 Account 当前实体中心，并复用公共字段、上传与 Markdown 控件。身份领取、管理权限等页面专属字段留在各自页面，不进入共享资料组件。文档、文件和资源目录的行内动作统一使用 LsResponsiveActions；文件与文档分页统一使用 NPagination。
  • 文档编辑页的 LsMarkdownEditor 是第三方编辑器实现级例外：保留其原有的模式切换、候选项与工具栏视觉结构，不将 NRadioGroup、NButton 或 NInput 的通用皮肤套入编辑器内部。页面其余字段仍使用标准 Naive UI；验收时确认编辑器模式、源码与对象候选项和统一化前版本一致。
  • 文档创建/编辑页的文档标签与实体资料管理页的公开文档分组统一使用 LsFormList。两处都允许添加、删除、拖拽及按钮排序，并按顺序提交；标签错误必须就近阻止保存。公开文档分组只出现在 Team、Member 和 Virtual 实体，Customer 不显示；缺少 team.entity.profile.manage 时展示只读内容并禁用列表变更，不发写请求。

Team 成员离职¶

  1. 范围：Team 的 /members 与 /member-edit，用于具有 team.member.remove 的管理员办理成员离职；成员本人的自助离队申请不在此规则范围。
  2. 行为：管理员操作必须显示为“离职”，确认后直接把成员设为已离队并使现有会话失效，不得为管理员创建待审离队申请。资料、角色、对象标识、业务关系与任期历史必须保留，Team owner 不得离职。
  3. 实现：列表使用 LsResponsiveActions 的危险操作，详情管理区使用 LsButton variant="danger"；两处统一调用 POST /memberDeparture/depart，成功后刷新成员列表和详情并通过全局反馈显示“成员已离职”。
  4. 适配：桌面端显示图标与“离职”文字；移动端收入更多操作，不取代“管理/查看”主操作。键盘、触控、读屏和文本放大沿用公共按钮与响应式操作组；确认文案必须同时说明会话失效与历史保留，不依赖颜色传达风险。该操作不包含动效，减少动态不需要额外例外。
  5. 状态：请求期间按钮显示加载并阻止重复提交；成功后成员显示“已离队”且不再显示离职入口；失败时保留当前页并显示服务端原因。缺少 team.member.remove 时列表入口保持禁用并说明 Permission，详情不显示危险区；加载与空数据不产生该操作。
  6. 例外：成员本人仍按 member.departure_mode 使用自助申请、取消和审核流程；这是成员主动离队与管理员办理离职的责任边界，不允许扩展到其他危险操作。
  7. 验收：Vitest 锁定两个管理员入口的“离职”文案、/memberDeparture/depart 请求与旧“发起离队申请”文案移除；后端成员生命周期测试确认一次操作直接生成已批准记录、关闭任期且保留 Entity。发布前运行 npm test、npm run typecheck、Team E2E、完整静态构建与文档构建。

Team 申请字段管理¶

  1. 范围：Team 的 /join-fields、/join-fields/new、/join-fields/:id，用于团队管理员维护加入申请表结构和审批后转存规则。
  2. 行为：列表必须同时展示启用和停用字段，并支持按名称/标识搜索及按启用状态筛选；创建、查看和编辑使用独立路由。字段标识创建后只读；删除已有提交记录的字段必须失败并提示改为停用。禁止在列表中常驻编辑器、隐藏停用字段或把字段排序改为仅支持拖拽。
  3. 实现：列表使用 LsListToolbar、LsEmptyState、LsAsyncState 与连续边界；表单使用 LsField、LsFormList、Naive UI 控件、LsInlineError 和 LsButton。选项以有序的“显示名称 + 提交值”编辑并兼容历史字符串或对象格式；布尔设置使用 NSwitch，状态使用 LsStatusTag，动效只使用公共令牌。
  4. 适配：桌面与移动端均为单列任务流；320px 下工具栏、选项和命令按钮纵向排列，交互目标不小于 44px。键盘可完成搜索、筛选、选项增删排序、保存和删除确认；文本放大后标签与说明自然换行；减少动态时取消列表位移。
  5. 状态：首次加载显示结构骨架，无字段与筛选无结果使用不同文案，读取和写入错误只在对应区域显示。team.join_field.read 控制列表和详情读取，team.join_field.write 控制创建、保存、删除及转存候选；只有读取权限时详情为只读模式，已知缺少权限时不得发起受保护请求。停用字段保留历史值并可重新启用。
  6. 例外：转存候选通过申请字段专用接口读取，只暴露当前团队人员 Entity 字段摘要，不额外要求 team.entity_field.manage；这是为了保持 team.join_field.write 已有的完整转存配置语义。除此之外无例外。
  7. 验收：Vitest 检查公共组件与导航契约；Playwright 覆盖启用/停用列表、选项校验、转存选择、只读权限和零越权请求，并在 320、375、768、1024、1440px 检查无横向溢出；后端测试锁定管理列表与公开表单的不同过滤范围。

Transaction¶

  • 壳层、顶栏、页面标题、工具栏和按钮遵守公共组件；移动端顶栏“登记流水”进入操作菜单，不显示孤立加号。
  • /new 的 entities/customers 必须先归一化；响应缺字段时表单继续渲染并禁用对应字段，真实请求失败显示区域错误。
  • 流水、发单绑定、客户余额是集合页。统计页是分析任务，可使用日期工具栏，但仍遵守控件尺寸和状态规则。
  • 流水、发单绑定、客户余额与余额明细的页面级无数据统一使用 LsEmptyState；统计小卡中的无数据说明属于局部分析状态，不扩展为大面板。
  • 流水、余额、绑定的 Entity 与 Customer 列使用 LsEntityIdentity；所有数据表使用 NDataTable，表单普通字段使用 LsField，页面标题直接使用 LsPageHeader，不保留仅转发参数的应用包装。

Admin¶

  • 用户、团队、管理员、角色、审计使用统一工具栏、结果数量、表格/连续列表和 NTag。
  • 上述五个主目录的无结果统一使用 LsEmptyState，不得在 panel 内再次嵌套一层空面板。
  • 平台命令搜索保留 Ctrl/Cmd+K 与 / 快捷键，是应用专属例外；其结果行不使用悬浮卡片。
  • 系统状态只读自动更新，不提供“重新检查”；所有错误区域无重试按钮。
  • 平台数据表使用 NDataTable；状态统一使用 LsStatusTag，调用端只传语义类型与可读文案。页面标题直接使用 LsPageHeader，不得保留只改名转发 back 的包装组件。

Account¶

  • 保留认证与团队选择专属布局，不套用管理侧栏；根部必须使用统一主题。
  • /identity/current 使用独立“当前实体中心”壳层，不复刻 Team 工作台：桌面采用轻量顶栏、固定身份摘要栏和单任务内容区；移动端把身份摘要放在内容顶部，并使用三等分的“资料 / 对象字段 / 角色权限”路由导航。表单保存栏固定在安全区上方。
  • 身份摘要始终展示类型、名称、@slug、所属团队和“切换身份”，不展示父会话或真实账号带来的管理暗示。Team 身份和基础账号使用解释性空状态，不伪装成可编辑表单。
  • 资料页按当前类型切换字段，客户附带服务归属；对象字段即使为空也保留稳定入口并解释由团队配置；角色权限全部只读。草稿键必须包含全局 entity_id，身份变化时冻结旧草稿和保存动作。
  • 团队和身份候选复用 LsEntityIdentity。认证失败允许“重新登录”；提交身份切换失败允许再次提交，这是用户任务恢复，不是数据刷新。
  • 团队目录和身份候选没有数据时使用 LsEmptyState；认证表单内的字段反馈不是页面空状态。
  • 团队选择使用 NModal、NButton 和有细分隔线的连续列表；加载、空和错误留在弹层内容区，关闭弹层后焦点回到触发入口。

Account 登录页原生按钮例外¶

  1. 范围：仅适用于 account/login 的登录方式分段按钮和密码可见性按钮；注册、团队、身份及其他 Account 页面不适用。
  2. 行为：验证码登录与密码登录必须保持同一行并各占一半，当前方式以选中表面明确标识；密码可见性按钮只切换输入内容是否可见。禁止把此例外扩展到提交、获取验证码或其他表单命令。
  3. 实现：登录方式沿用 v0.1.4 的两个原生 button、role="tab" 与 aria-selected，由两列 .mode 网格承载；密码可见性沿用带可读 aria-label 的 44×44px 原生图标按钮。颜色只使用 --cloud、--ink 与 --muted-ink，提交仍使用 LsButton。这是原生标准控件源码契约的具名例外。
  4. 适配：桌面与 320px 移动端均保持两个登录方式同排，按钮触控高度至少 44px；键盘按文档顺序访问并使用全局 :focus-visible，读屏可识别 tablist、选中状态及显示/隐藏密码文案；文本放大时允许标签内部自然换行但不得拆成上下两项；不包含动效。
  5. 状态：分段按钮只包含已选与未选状态，密码按钮只包含显示与隐藏状态；加载、错误、过期登录及禁用状态继续由原表单和提交按钮处理，不涉及权限、Ability、空数据或额外恢复流程。
  6. 例外：Naive UI 2.44.1 的 NRadioGroup 会在两个选项之间插入额外分隔节点，无法直接复现旧版稳定的两子项网格与视觉结构，因此保留 v0.1.4 原生实现。公共组件可无额外结构节点地复现相同语义、布局和样式时，本例外失效并应移除。
  7. 验收：npm test 的源码契约锁定仅这三个原生按钮；tests/frontend.spec.ts 在桌面和移动项目中断言两个 tab 数量为二且纵坐标一致，并继续检查两种登录表单均可操作；发布前运行 npm run typecheck、对应 E2E 与 npm run build。

Chat¶

  • 保留会话专属布局，不套用管理侧栏；根部使用统一主题，团队与参与者使用 LsEntityIdentity。
  • 会话时间线可采用消息气泡，这是按发送者和时间组织内容的具名页面例外；气泡只能出现在消息时间线，不得扩展到会话导航、参与者或搜索结果。会话列表必须使用 NButton 驱动的连续分隔结构，键盘焦点与 hover 都只改变表面色，不浮起、不加新边框。
  • 聊天团队选择页没有可用团队时使用 LsEmptyState。会话列表、未选择会话、空消息时间线和参与者详情都是聊天专属局部状态，保持紧凑布局，不使用页面级空面板。

检查¶

每次修改上述应用时，在 PR/变更说明中链接本页对应条目；若页面需要偏离公共组件、断点、状态或动作层级，先在本页新增具名例外、理由、影响范围和自动化断言。
