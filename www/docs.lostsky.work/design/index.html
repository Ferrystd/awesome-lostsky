LostSky Style & Design System¶

后台界面的完整、可执行规范见后台设计规范。本页只保留产品级双界面原则；组件参数、页面模式、状态权限、响应式、应用例外和验收要求以后台规范板块为唯一正文来源。

双界面体系¶

LostSky 共享同一套名称、青空主色和清晰表达，但按使用意图拆成两套不可混用的界面语言：

  • www.lostsky.work 与 {slug}.display.lostsky.work 是前台展示页，设计本身承担品牌表达与公开内容阅读任务。
  • account.lostsky.work、team.lostsky.work、chat.lostsky.work、transaction.lostsky.work 等是后台操作页，设计服务于连续、准确地完成任务。

两类页面可以共享品牌标识、语气和基础无障碍标准，但不得为了“统一”而使用相同的页面构图、信息密度或装饰强度。跨域跳转应保留清楚的入口文案，让用户知道自己将从品牌官网进入工作台。

前台展示页¶

视觉方向¶

官网延续历史陪玩运营工作室的深色长页叙事：#020617 深空基底、青蓝主色、紫色辅助光、固定品牌背景和少量玻璃层次。它应像白昼退入深空后的天光，冷静、敏锐、有余韵，而不是通用 SaaS 首页或电竞 HUD。

  • 首屏先建立品牌记忆，再说明增长策略、成员孵化和数据系统。
  • 使用非对称或大尺度品牌构图、宽松段落节奏和展示字体；不套用后台标题栏、工具栏或仪表盘栅格。
  • 青蓝与紫色渐变用于背景、按钮、数据图形和环境光，不使用渐变文字。
  • 玻璃效果只用于固定导航、首屏方法摘要和最终转化区等有层级意义的位置，不把每段内容都做成玻璃卡片。
  • 业务内容优先使用连续信息带、真实媒体和大段叙事；避免相同尺寸的图标卡片重复堆叠。
  • 可以在保留核心文案、深色基底、青蓝/紫色品牌记忆和长页章节的前提下优化构图、交互与可读性，不把“历史风格”理解成禁止修正问题。

团队 Display 主页复用同一深空、青蓝和少量紫色环境光，但以阅读团队 Profile、公开字段、文档和实体目录为主。所有团队使用统一模板，不读取团队配色；实体详情将 Profile 现有 intro_image 作为唯一的全宽 Hero 背景，放入固定高度容器并使用 cover 居中裁剪，不再叠加站点背景或在正文重复图片；无人物图时才显示头像或排版式环境光回退。公开角色作为实体身份信息使用紧凑标签展示，说明保持可读且不暴露权限。公开文档使用独立的纯净深色阅读壳层，标题与正文建立明确尺度差，正文保持 65–75 字符行宽，并完整呈现 Markdown 的标题、列表、引用、代码、表格和媒体层级。实体与文档采用连续列表和正文流，不堆叠重复卡片墙，也不显示联系方式、加入 CTA 或聊天动作。

团队 Shop 同属前台展示页。它复用 Display 的深空基底、展示字体和青蓝/紫色环境光，以团队 Hero、品牌介绍和交错的大幅商品媒体形成连续陈列；商品无封面时使用明确的排版式品牌回退。 结账、客户绑定和取消确认可使用 Naive UI，但只作为购买流程的局部控件，不把整个商城做成后台工作台。

排版与空间¶

  • 展示标题使用自托管 Barlow Condensed，中文回退到系统中文字体；正文使用系统中文字体栈。
  • 展示标题最大 88px、字距不小于 -0.035em，标题使用平衡换行；正文行宽控制在 65–75 个字符内。
  • 以 4px 为基础节奏，章节间距可使用 48、72、96、128px，形成比后台更明显的呼吸与叙事停顿。
  • 品牌媒体和关键面板圆角最大 16px；普通内容不默认装卡片。按钮可在明确 CTA 语义下使用全圆角。

交互与动效¶

  • 官网关键动效为 240–420ms；只动画 transform、opacity、clip-path 和必要滤镜，内容默认可见。
  • 首屏允许一个有明确品牌作用的环境动效；禁止每个章节统一淡入和无意义视差。
  • 移动端必须提供完整导航，触控目标不小于 44×44px；所有交互有键盘焦点态，核心内容不依赖 hover。
  • Markdown 中的 Entity 引用使用语义按钮和单一展开式资料卡；同一引用再次触发即收起，展开状态通过 aria-expanded 暴露，团队、成员、客户和虚拟实体使用一致结构与可辨识类型图标。
  • prefers-reduced-motion 下取消位移、视差和视频自动播放；移动端与省流量模式使用静态媒体回退。

媒体¶

  • 官网必须包含可追溯的真实图片、产品画面、视频或已有品牌视觉资产，不用纯色矩形冒充素材；所有媒体登记在 frontend/media/manifest.json。
  • 首屏视频如启用，应为 5–8 秒、静音、循环，并提供海报图；图片输出 AVIF/WebP 和回退格式，声明尺寸与焦点。
  • 网络素材必须记录来源和许可证。不得临时依赖未登记的第三方头像或不可控图片接口。

后台操作页¶

视觉方向¶

后台是任务型产品界面，采用明亮、高可读、克制的 restrained 色彩策略。界面应退到任务之后，让列表、表单、状态和下一步操作成为视觉中心。

  • 页面使用纯白与 cloud 表面；sky-lost-strong 只用于主操作、焦点、当前导航和必要状态。
  • 禁止蓝紫渐变、装饰性玻璃、霓虹、大面积光晕、品牌首屏动效和展示型巨字。
  • 使用固定字号层级、系统字体、标准导航与熟悉控件；后台的价值来自一致与可信，不来自惊奇。
  • 信息密度可以高于官网，但必须通过分组、留白、边界和清楚标签维持可扫描性。

布局与信息架构¶

  • 团队后台页面使用 frontend/apps/team/src/components/AdminPage.vue 作为内容容器，使用 AdminPageHeader.vue 生成标题、说明、返回入口和操作区。
  • wide 用于列表，content 用于详情与审核，form 用于单列表单；页面保持 16/24px 纵向节奏。
  • 后台采用「列表路由 → 独立任务路由」：查看、创建、编辑、审核页面必须可刷新、返回和直接分享链接。
  • 列表页只承担搜索、筛选、概览和进入任务；不得常驻主从编辑器。弹层只承载简短、低风险的单步输入或确认。
  • 表单字段采用单列纵向节奏，内容宽度通常不超过 42rem；禁止为了填满桌面宽度横排多个文本输入框。
  • 前端信息架构以 entity 为统一主体概念，成员只是 teamMember 实体类型之一；不得把“成员”和“实体”设计成并列入口或重复流程。仅处理成员专属业务时使用“成员”，跨类型能力统一使用“实体”并在结果中标明具体类型。

组件与状态¶

  • 标准表单控件使用 Naive UI，主题入口为 frontend/packages/ui/src/naive-theme.ts；已有同类组件时不再以原生元素和页面私有 CSS 重造。
  • 设置页按数据语义统一控件：布尔值使用开关，2–3 个需要比较含义的互斥选项使用带标题与说明的单选卡，更多或无需解释的选项使用下拉框；不得直接展示枚举 case name。移动端默认单列排列并保持至少 44px 触控区域，宽屏再增强为多列。
  • 组件按业务路由导入，不在应用根节点无条件加载整套组件库。
  • 输入、选择、按钮、复选框、弹层和反馈必须覆盖默认、悬停、聚焦、激活、禁用、加载及错误状态。
  • 加载使用与内容结构相符的骨架；空状态说明下一步；错误信息靠近问题并提供恢复路径。
  • 后台列表统一使用紧凑搜索栏、必要的单一分类筛选和结果数量；搜索图标留在输入框内，连续数据优先使用有边界的列表，不把每项重复包装成独立卡片。
  • 保存、删除和权限/能力原因等短时反馈使用全局提示函数，默认在 3–5 秒内自动消失并支持关闭；不得在侧栏、页面左右两侧或多个组件中重复常驻同一错误。字段校验与阻断页面继续操作的错误仍就近展示。
  • 缺失能力或权限的既有入口保持结构稳定时，以清楚的禁用态、title 和无障碍说明解释原因；禁用上传能力不得用新增的替代按钮改变原有工具栏结构。
  • 产品交互通常为 150–220ms，只表达状态变化和空间关系，不使用编排式页面入场动画。

后台动效统一使用 @lostsky/ui 的语义令牌：--motion-instant 100ms、--motion-fast 150ms、--motion-base 200ms、--motion-slow 320ms；标准状态变化使用 --ease-standard，进入和空间展开使用 --ease-out，退出使用 --ease-in。候选层、遮罩、异步状态和列表重排分别复用 ls-popover、ls-backdrop、ls-state 与 ls-list，列表不得使用 appear 编排首次渲染。持续动画只用于正在加载的进度或骨架；prefers-reduced-motion 下取消位移并将动画与过渡缩短到近乎即时。

共用基础¶

颜色¶

产品基础颜色使用 OKLCH；官网历史品牌锚点可保留现有 Hex 值，但应通过语义变量引用，避免在组件内散落新颜色。

:root {
  --sky-void: oklch(0.105 0.018 225);
  --sky-night: oklch(0.155 0.026 218);
  --sky-lost: oklch(0.500 0.105 185);
  --sky-lost-strong: oklch(0.405 0.092 183);
  --afterglow: oklch(0.705 0.155 55);
  --daylight: oklch(1 0 0);
  --cloud: oklch(0.965 0.006 210);
  --ink: oklch(0.175 0.018 218);
  --muted-ink: oklch(0.455 0.022 215);
  --line: oklch(0.885 0.012 210);
  --danger: oklch(0.555 0.205 25);
  --success: oklch(0.515 0.125 155);
  --warning: oklch(0.690 0.150 75);
}

无障碍与质量¶

  • 正文对比度至少 4.5:1，大字号与非文本控件至少 3:1；颜色不能作为唯一状态信号。
  • 页面保留顺序正确的标题层级、跳到主要内容链接、可见焦点和符合视觉顺序的键盘导航。
  • 数据使用 font-variant-numeric: tabular-nums，不为“技术感”额外引入等宽字体。
  • 层级优先依靠留白、边界和表面差异；装饰性边框与大范围柔和阴影不同时使用。
